1. ノイズ・遅れ・剛性更新を外した baseline を作り、`theta_cmd`, `theta_ref`, equilibrium の静的関係を確認した。

3. yaw 回転時に `theta_cmd` が `theta_ref` 側へ寄る問題を、IMU 観測の局所観測可能性と WEKF の過剰な積分更新として切り分けた。
4. いったん ad-hoc な安定化として、観測可能部分空間への projection と剛性更新量の制限を入れた。
5. equilibrium がわずかに `ref` からずれる問題は、推定器ではなく平衡ソルバの収束精度の問題として分離し、静力学残差 refinement を入れた。
6. その後、計画文書に沿って ProbTF ベースの local Laplace / WEKF 更新へ実装を整理した。
7. 微小ノイズを戻したとき、見た目には揺れないほど小さいことを確認し、振幅を大きくして launch 反映を確認した。

## 重要な設計判断

- `K_est` は推定器の内部状態、`K_exec` は補償器が実際に spring compensation へ使う値として分ける。
- estimator の更新を直接 actuator 側へ入れず、`K_exec` を `K_est` へローパス的に追従させることで、推定の瞬間的な揺れと実行側の揺れを分離する。
- `/deflecomp/kp_hat` は既存ツール互換のため残すが、意味としては `K_est` とする。新規の debug viewer や今後の調査では `/deflecomp/kp_est` と `/deflecomp/kp_exec` を明示的に見る。
- yaw などの不可観測方向は、関節名の決め打ちではなく、現在姿勢・IMU frame・重力方向観測モデルの Jacobian から判定する。
- まずは IMU 1 サンプルごとの local Laplace 更新として実装し、必要になった段階で window / batch 推定へ拡張する。
- debug 用の可視化は `rqt_plot` で代替できるものから始めるが、今後込み入った確認を入れられるよう、専用パッケージ `deflecomp_debug` として切り出す。
