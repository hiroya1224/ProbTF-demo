## 主な作業の流れ

1. WEKF が局所解へ固着したときに、局所線形化だけでは復帰できない問題を、background の particle supervisor で大域的に見直す方針にした。
2. 最初は「良さそうな候補」「共分散が小さい軸だけ scan」などの gate も入れたが、YAGNI の方針で plain な axis-grid scan に簡素化した。
3. 初期 `K` をロボットごとの固定長配列で持つのをやめ、`kp_min` / `kp_max` から全関節共通の初期値を作る構成にした。
4. 外力負荷を使って `K` が更新されるか確認するため、sim 側に external wrench topic と `apply_frame_load.py` node を追加した。
5. 外力は world 相対を default とし、必要な場合だけ local 相対も指定できるようにした。
6. particle scan を同期的に回すと通常の EKF/command cycle を止めてしまうため、scan 本体は background process へ逃がした。
7. process worker は main process と Pinocchio data を共有せず、URDF path と設定だけから独立 evaluator を構築する形にした。
8. particle correction で `K_est` が急に飛びすぎるため、zealot/pursuit mixture として候補へ部分的に寄せる設計にした。
9. `cmd` が `ref` に追従して見える問題を、`theta_cmd` 計算ではなく equilibrium `equiv` が `ref` へ合うように command を再計算する問題として整理した。
10. particle candidate validation を hard reject にすると、WEKF が固着した状態で particle が `P_est` を散らかす役割を失う可能性があることを TODO として残した。

## 重要な設計判断

- particle supervisor は EKF の代替ではなく、通常の WEKF cycle の裏で `K_est` を監視・補正する supervisor とする。
- `theta_cmd` の通常 publish cycle は particle scan の計算時間に引っ張られてはならない。
- worker process は main loop の `RobotArm.data` / Pinocchio mutable state を共有しない。
- particle が見つけた候補は `K_exec` へ直接入れず、まず `K_est` / `K_exec_target` に反映し、`K_exec` は従来どおり smoothing で追従させる。
- particle correction は `x_est` を候補へ全置換するだけでなく、active 軸の covariance reset によって WEKF を再び動かす効果も持つ。
- sim 外力負荷は、実機の追加重りに近い確認ができるよう world 相対 force を default とする。
- `cmd` の目的は `cmd == ref` ではなく、ばね・重力・外力を含む equilibrium が `ref` に一致することである。

## 未解決・今後の論点

- particle candidate validation を完全な hard reject にすると、WEKF が局所的に固まっている場合に particle の「推定を散らかして復帰させる」役割を殺す可能性がある。
- とくに `log_kp_process_noise_var` が小さく、`P_est` が縮んだ状態では、particle correction が入らない限り `P_est` の reset も起きず、WEKF がほぼ動かなくなる。
- 次の修正では、validation を完全な hard reject にせず、例えば以下を検討する。
  - particle 候補が current よりわずかに悪いだけなら、`x_est` は動かさず `P_est` だけ inflate/reset する。
  - `score_best - score_current` に許容 margin を設け、弱い悪化なら recovery correction を許す。
  - validation は短期 window だけでなく、古い window / recent window の両方で見る。
  - WEKF の `est_update_skipped_reason == no_observable_information` や update norm が長時間ゼロの場合は、particle correction gate を緩める。
  - correction 適用時に `x_est` を particle 候補へ全置換せず、blend する。
- debug では `particle_scan_reason`, `validation_score_current`, `validation_score_best`, `validation_gain_per_obs`, `particle_correction_applied`, `kp_cov_diag` を同時に見る。
- `particle_pursuit_mixture_weight` は反応性と安定性の trade-off になるため、実機や負荷付き sim で調整が必要。
