# docs/logs 作業ログ記述ルール

このディレクトリの作業ログは、commit log を基準にして日付別に作成する。
日付や対象範囲を推測で広げず、各コミットの時刻を基準に機械的に分類する。

## 日付の切り方

- ログの日付は `UTC+02:00` の日付で決める。
- これは日本時間では「翌 07:00」で日付が変わる、という意味である。
- 日本時間 06:59 までは前日ログに含める。
- 日本時間 07:00 以降は当日ログに含める。
- 「作業が前日から続いていた」などの理由で、07:00 以降のコミットを前日ログへ含めない。

例:

- `2026-07-12 06:59 JST` のコミットは `2026-07-11.md` に書く。
- `2026-07-12 07:00 JST` のコミットは `2026-07-12.md` に書く。
- `2026-07-12 10:20 JST` のコミットは `2026-07-12.md` に書く。

## ファイル名

- ファイル名は `YYYY-MM-DD.md` とする。
- `YYYY-MM-DD` は上記の `UTC+02:00` 基準の日付である。
- 対象日のログが存在しない場合は新規作成する。

## 情報源

- 原則として `git log` の commit hash、commit timestamp、commit subject を基準に書く。
- 各コミットの内容は `git show --stat` や関連 diff を確認して要約する。
- 未コミットの作業を書く場合は、commit 履歴とは分けて「未コミット作業」などと明記する。
- 時刻を書く場合は、曖昧な「今日」「昨日」ではなく、具体的な日付と時刻を使う。

## 基本構成

各日のログは、必要に応じて以下の順で書く。

1. `# YYYY-MM-DD 作業ログ`
2. 対象範囲の短い説明
3. `## コミット履歴`
4. `## 主な作業の流れ`
5. `## 重要な設計判断`
6. `## 追加・調整した主な設定と topic`
7. `## 検証メモ`
8. `## 未解決・今後の論点`

該当項目がない場合は省略してよい。
ただし、TODO や未解決事項がある場合は、同じ日のログ末尾に `## 未解決・今後の論点` として残す。

## コミット履歴の書き方

- 1 コミットを 1 つの bullet として書く。
- 形式は以下を基本にする。

```md
- `abcdef0` 2026-07-11 15:36 `commit subject`
  - 主要な変更点を書く。
  - 実装意図、影響する module、追加 topic / param / node などを書く。
```

- commit subject は `git log` の表記を尊重する。
- typo が含まれていても、subject は勝手に直さない。
- 詳細 bullet は実装の事実を中心にし、推測や評価は控える。

## 主な作業の流れ

- 複数コミットにまたがる流れを、時系列または設計上の依存順にまとめる。
- commit 履歴の単なる再掲ではなく、「なぜその順に変更したか」が分かる程度に整理する。
- ロジック変更、debug 導線、config 整理、検証追加の関係を明確にする。

## 重要な設計判断

- 後から読み返したときに挙動の前提が分かる判断を書く。
- 例:
  - supervisor は EKF の代替ではなく background の監視・補正装置である。
  - `K_est` と `K_exec` は役割を分ける。
  - `theta_cmd` は `cmd == ref` ではなく、equilibrium が `ref` に一致することを目的にする。
- 実装から自然に読み取れる細部を過剰に列挙しない。

## 設定・topic・node

- config parameter、ROS topic、ROS node、command など、運用時に参照しそうな名前をまとめる。
- 既存の名前を正確に書く。
- 廃止した parameter がある場合は、廃止理由を短く書く。

## 検証メモ

- 実際に実行した test、build、smoke test を書く。
- 実行していない確認を実行済みのように書かない。
- 失敗や未確認が残る場合は、そのまま明記する。

## TODO・未解決事項

- TODO は原則として該当日のログ末尾に書く。
- 別日のログに追記しない。
- TODO は「何が問題か」「次に何を見るか」が分かる粒度で書く。
- 調整値が未確定の場合は、対象 parameter と観測すべき debug signal を書く。

## 禁止事項

- 日本時間の暦日だけでログ日付を決めない。
- 作業の気分や流れで、07:00 以降のコミットを前日ログへ含めない。
- commit log を確認せずに、記憶だけでログを作らない。
- 誤った日付のログへ TODO を追記しない。
- 既存ログの無関係な内容を書き換えない。
