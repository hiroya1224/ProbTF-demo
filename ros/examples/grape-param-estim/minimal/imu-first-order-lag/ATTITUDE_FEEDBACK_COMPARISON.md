# 実IMU：姿勢更新を組み込んだモデル＋余剰レンチの再構成

2026-11-06。ユーザーの選択「各方式の姿勢推定を動力学の伝播へ組み込む構成から改修する」に対応する独立比較。元の `publication/imu_native_20261031` とmocap版、独立人工IMU比較は変更しない。普段の推定の既定も重力だけの観測のままとする。

## 固定するもの

元のfailure1・failure2・successのIMU列、取得時刻、指令、機体同定値、全16パラメータの共同共分散、推力・gyro・accelの一次遅れを使う。保存された同一点の式と導関数を再評価するが、再最適化・共分散の再同定はしない。`fit_results.npz` を明示して読み、別の再生用 `arrays.npz` と混同しない。入力・同定値・実行ソースのSHA-256を記録する。

mocapは初期姿勢・位置・初期速度の整合だけに使う。継続mocap列は推定入力から取り除き、図を作る段階でのみ原時刻の黒い参照線へ渡す。初期速度の取得区間・indexも元の入力に残る。余剰レンチは元IMUから計算した値であり、mocapへ合わせるための外乱ではない。同じIMUから作るため、この再構成は独立データに対する予測精度試験ではない。

## 姿勢更新と物理伝播の接続

ゼロ抗力の今回のモデルでは、bodyの角運動と比力は世界姿勢に依存しない。元のモデル＋実使用余剰レンチの角運動を共通のcarrierとして使う。ただし、その絶対姿勢を観測後の姿勢へ代入しない。native区間の右増分

\[
\delta_k=(q_{k-1}^{\rm carrier})^{-1}\odot q_k^{\rm carrier}
\]

を、直前のgyro＋accel再帰候補へ作用させる。共通の31列の感度因子（機体・遅れ16、初期9、経験的な持続レンチ6）から

\[
L_{\delta,k}=L_{R,k}-R(\delta_k)^\top L_{R,k-1}
\]

を作り、同じsource列の端点間相関を相殺して増分共分散を求める。この各区間の周辺共分散を独立Bingham増分へ変換する部分はフィルタ近似であり、全時刻のパラメータ共有を厳密に積分した共同事後ではない。元のsource因子も保存する。

区間内の姿勢輸送には、native区間の回転増分を平均body角速度として時間配分する近似を使う。余剰トルクを含む角運動自体は共通carrierのRK4解であるが、その区間内角速度変化を姿勢lawへ厳密に再積分したものとは説明しない。

重力だけの分岐は既存Bingham観測更新と既存の保守的な加速度共分散方針を維持する。並進加速度を含む分岐は独立IMU実験の条件付きGaussianを持ち、二次・四次の観測係数を残す。初期姿勢と初期Binghamパラメータは両者で同一。並進加速度のAR事前は時定数0.7秒、初期標準偏差0.3 m/s²、定常標準偏差1.5 m/s²で、人工比較と同じ設定を使い、mocapを見て選び直さない。

物理並進は、各分岐の再帰姿勢候補のモーメントを使い、

\[
\dot p=v,\qquad
\dot v=E[R]\frac{F_{\rm actuator}+F_{\rm residual}}{m}+g
\]

で計算する。観測した加速度をそのまま代入するdead reckoningへの差替えではない。RK4の各段で同じ推力応答、実gimbal補間、余剰レンチ平均と全パラメータ感度を使う。区間内は開始時点の再帰候補とモデル増分だけを用い、区間終端の観測を過去へ戻さない。回転の平均・二次モーメントは同じ姿勢lawから一度照会して再利用する。

地磁気は新規取得時の現在出力だけに融合する。姿勢、条件付き加速度、次時刻の事前、CoGの位置・速度へは戻さない。現在出力の姿勢を使うCoG→FCの取付位置の照会だけには反映される。

区間への適用順序を守ることと、実時間で因果的に計算できることは別である。この比較は固定したオフライン同定と既存の中央local-polynomial窓による遅れ補正を使うオフライン再構成であり、実時間因果フィルタの性能とは説明しない。

## 帯の意味と近似

機体・遅れの全共同共分散は共通のsource因子として保持する。力／質量、アクチュエータ／余剰レンチ、取付位置に現れる同じパラメータの感度は、共分散化する前に加算・相殺する。位置の帯は、この一次感度と、未知な姿勢・時刻相関に対するスペクトルノルム／Minkowski上界、四つのsource群のCauchy上界を合わせた**周辺共分散の保守的な上界**である。経験的な持続レンチ源も含むため、任意の系統誤差を包含する保証ではない。完全な状態・パラメータの共同Gaussian事後とは呼ばない。

姿勢の帯は同じ出力lawから得る右body座標の局所共分散proxyをEulerへ写した±2σ。既存分岐はBinghamのmodal curvature、新分岐は全lawの \(M_{qq}=E[qq^\top]\) によるquaternion半角の二次モーメントproxyを使う。新分岐をAだけのBinghamへ置き換えていない。rpy曲線は代表quaternionのEuler角であり、Euler角の厳密な期待値ではない。どちらの帯も95%被覆保証ではない。

新分岐の有限19係数forward-KL射影、決定論的な多峰数値積分、有限反復誤差は記録する。有限の未収束で次の観測を止めない。共有する遅れ推定値や重なる平滑化窓の時刻間依存を、観測フィルタ内部で完全に積分していない点も明示する。モンテカルロ、coreの変更、分散floor、jitter、描画用の帯の縮小は使わない。

この実データでは、粗い固定求積だけではヨー方向に広がったlawのモーメントに誤差が出たため、新比較は数値積分の精細化を有効にする。最初にGH7／GH9の二則で正規化定数・19個の正規化特徴モーメント・回転平均を比較する。差が数値許容誤差1e-5を超えた場合は、粗い \(M_{qq}\) の固有基底でHaarノードをO(4)回転し、Haar32×32²／40×48²と局所GH9の二則で再積分する。MISの局所配分は1e-5。この配分は求積ノードの配置だけを変え、候補lawや分散は変えない。Haar測度と積分重みは直交座標変更で不変である。

これは有限の数値誤差制御であり、大域的な誤差保証ではない。最後の二則の差とdense ruleの使用maskを保存し、予算内で差が残っても最後の有限な積分結果で観測更新を続ける。観測や身体状態を棄却する品質閾値ではない。同じ設定を予測射影の全候補の正規化、観測後の積分、出力専用地磁気の積分へ渡す。独立人工IMU実験の既定は変更せず、任意の `quadrature_options` として追加する。実データの固定lawと独立Haar収束値を小さい回帰fixtureに残す。

## 要求された図と再現

各記録につきgyro・accel・xyz・rpy・余剰トルクの五図だけを保存する。gyro/accelは、実物理出力へ推定済みのセンサ一次遅れ \(\tau\dot y+y=x\) を順方向に適用して生値と比較する。元時刻区間でZOH、最初の生値を初期値とする。body出力は両分岐で共通なので曲線を二重に描かない。余剰トルクは実際に加えたbody重心まわりのNmで、角加速度残差ではない。

最新のユーザー確認「表示だけ省く。計算・共分散データは保持する」に従い、xyzはモデル平均だけを表示し、広いモデル位置の共分散帯は描かない。rpyは左に代表曲線、右に同じ曲線とIMU姿勢推定の±2σの全幅を示す。計算された分散の縮小や上書きはしない。参照mocapは元取得時刻のまま描く。全描画数値・表示から省いた位置標準偏差も各 `figure_data.npz` に、位置・右回転の全3×3周辺共分散を `trajectory_marginal_covariance.npz` に保存する。元の推定値・共分散の付録は旧publicationに残し、今回の限定PDFには追加しない。

リポジトリのルートから実行する。

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 /usr/bin/python3 \
  ros/examples/grape-param-estim/minimal/imu-first-order-lag/run_requested_comparison.py \
  --output /tmp/grape-attitude-feedback-refined-20261106 --jobs 3
```

求積の開始次数は `--quadrature-order`、精細Haar則は `--haar-radial` と `--haar-angles`、求積の局所配分は `--local-mixture-weight`、数値誤差制御は `--integration-tolerance`、有限射影回数は `--projection-iterations` で変更できる。これらは物理モデル・ノイズ・加速度の事前の設定とは別である。

全law、条件付き加速度、source因子を含む中間NPZは指定した出力先に残る。Gitへはコード、図、描画数値、小さいmetadataだけを選んで保存する。

実行途中で表示専用の指定が変わった今回の記録は、保存済みの再構成を `refresh_requested_figures.py --output <実行先>` で描き直す。推定を再実行せず、描画数値の全キー・全配列と再構成NPZのhashが不変であることを検査する。元の計算ソースと後のrendererのhashを別phaseとして `render_manifest.json` に記録する。
