# 物理側の動力学（2026年10月18日）

ユーザーの「物理更新を、振動もしうる安定した物理シミュレーションへ変えたい」という指示により、観測融合デモの仮想身体を変更する。4センサ条件と手先IMU条件に共通の `MovingSwitchScene` が同じ動力学を使う。新しい動画の録画やRViz設定の変更は含めない。

## 方程式と物理パラメータ

送信された関節位置指令を \(u\)、物理身体の関節角を \(\theta\)、角速度を \(v\) とする。

\[
\dot\theta=v,\qquad
M(\theta)\dot v+C(\theta,v)v+g(\theta)
  +K_{\mathrm{sim}}(\theta-u)+Dv=0.
\]

URDFのリンク・棒・カメラの質量と慣性から、PinocchioのRNEAで慣性・Coriolis・重力を計算する。逆動力学の解析微分もPinocchioの `computeRNEADerivatives` を使う。[公式API](https://gepettoweb.laas.fr/doc/stack-of-tasks/pinocchio/master/coverage/index.include_pinocchio_algorithm_rnea-derivatives.hpp.html)を参照する。対象はこのURDFの6個の有界回転関節である。

真のばね定数は従来どおり \([350,125,95,60,40,30]\) Nm/rad。ユーザーの追加指示「ダンピング係数はかなり大きく」に従い、減衰は物理設定 `plant.dynamics.damping_ratio=2.0` を既定とする。最初の実装案0.1の20倍であり、初期状態の慣性を使って

\[
D_i=2\zeta_i\sqrt{K_i M(\theta_0)_{ii}}
\]

で一度だけ決める。単位はNms/rad。この対角式は減衰を設定する簡単な規約であり、連成系の各モードの減衰比が厳密に2.0になるという意味ではない。既定値は強い減衰を与える実装選択であり、実機に較正済みの物理値ではない。減衰を零に設定することもできる。実際に使ったDを診断へ残す。低減衰0.1の試験は振動を表現できることの確認であり、既定の動作とは区別する。

今回のURDF・初期指令では、実際のDは約 `[56.99, 45.60, 41.90, 8.22, 7.89, 1.84]` Nms/radである。

初期の「開始前から重力でたわんでいる」条件を維持するため、初期指令に対する安定平衡を一度だけ求め、\(\theta_0=\theta_{\mathrm{eq}}(u_0),v_0=0\) で開始する。その後は\(\theta,v\)を保持して積分し、指令を保持しても運動が続く。平衡点への毎周期の置換、人工的な正弦波、指令の追加フィルタ、指令速度上限による実角速度のclipは行わない。

## 積分と時間

C++ライブラリをcatkin build時に構築し、PythonからC ABIとctypesで呼ぶ。Python実行時の自動コンパイルはしない。1回の呼出しで外側の更新区間全体を積分する。

実際の経過時間を既定最大1 msの内部刻みへ分割する。\(N=\lceil\Delta t/h_{\max}\rceil\) の整数境界 \(\Delta t\,i/N\) を使い、時刻の反復加算で極小の余り区間を作らない。送信指令の区間始点・終点を同じ区間内で線形補間し、隠れた参照フィルタは加えない。時刻を進めない呼出しでは関節角・角速度を進めず、同時刻の異なる指令は明示的に拒否する。外側の120 Hzは目標周期であり、遅延時も実際のdtを使う。

各内部刻み\(h\)で、陰的中点法を解く。未知の次角速度を\(v_1\)とすると、

\[
v_m=\frac{v_0+v_1}{2},\quad
\theta_m=\theta_0+\frac h2v_m,\quad
a_m=\frac{v_1-v_0}{h},\quad
\theta_1=\theta_0+hv_m,
\]

\[
r(v_1)=\operatorname{RNEA}(\theta_m,v_m,a_m)
       +K(\theta_m-u_m)+Dv_m=0.
\]

NewtonのJacobianは

\[
\frac{\partial r}{\partial v_1}
=\frac1hM+\frac12\frac{\partial\tau}{\partial v}
 +\frac h4\frac{\partial\tau}{\partial\theta}
 +\frac12D+\frac h4K
\]

を使う。有限差分や乱数による動力学微分ではない。残差を検査してline searchし、解けない内部区間は刻みを半分にして再試行する。上限まで解けなければ明示的に失敗し、平衡姿勢へ切り替えて成功扱いにはしない。

陰的中点法は線形の無減衰振動を陽Eulerのように増幅させず、減衰付きでも振動を表現できる。[Hairerの数値積分講義](https://www.unige.ch/~hairer/poly_geoint/week2.pdf)に基本的な中点法の説明がある。この非線形ロボット全体の厳密なエネルギー保存や、任意の刻みに対する無条件安定性は主張しない。小さい内部刻み・残差検査と、刻み収束・エネルギー・減衰振動の試験で挙動を確認する。

関節の機械的ストッパへ到達したときは、到達時刻を区間分割で求め、\(M(\theta)\) の計量による片側速度制約への完全非弾性投影を使う。他の関節への連成した衝撃も保つ。静止した限界では反力の符号を検査した拘束中点法を使い、力が内向きになれば離れる。衝撃損失はエネルギー診断へ分けて記録する。これは関節限界の処理であり、下記のパネル等への接触反力とは別である。

積分に失敗した場合は、実状態・送信指令・時刻・経路を呼出し前へ復元する。失敗試行の反復回数等は `last_advance_failed`・`last_advance_error`・`advance_diagnostics_scope` とともに区別する。成功フレームへ失敗試行の姿勢を採用しない。エネルギー収支の残差を記録し、残差を消すために実状態を再スケールしない。

## 描画・衝突・センサの境界

不透明なロボットは積分された実角度、半透明の剛体ロボットは実送信指令のFKで描く。候補分布は従来と同じ推定結果であり、実姿勢へ再中心化しない。物理フレームに実角速度・実角加速度・積分診断を追加し、物理記録の旧 `equilibrium` は `actual_joints` へ改称する。動的な実角度を平衡解と呼ばない。

ユーザーの最新の「干渉は一旦どかしてしまっていい」に従い、**外部障害物との干渉判定は一時無効**にした。`plant.collision_checking=false` が既定である。この設定では途中・終点のcollision box生成と距離検査を実行しない。実際の棒先端の6 mm距離条件だけを `reached` と到達ランプへ使い、既存statusに `Collision checks: OFF | lamp: distance only` を加える。未検証を無干渉と扱わないため、`clearance_m`・`collided`・`minimum_clearance_m` はnull、`reach_condition` は `distance_only_collision_unchecked` とする。ボード・パネル・ボタン等の描画は保持する。

`plant.collision_checking=true` に設定すれば、内部刻みの実経路を従来の関節・形状変位分解能でも分割する詳細検査へ戻る。有効時の `collided` は一度発生したら保持し、距離条件に加えて検査に禁止干渉がなかった場合だけ到達とする。有限分解能の検査であり、連続衝突検出による全時刻の厳密保証ではない。移動上界による検査省略は検討したが、最新の一時無効化指示を受けて実装から除いた。パネルやボタンへの接触反力は未実装であり、外部障害物との完全な接触力学シミュレータとは説明しない。関節の機械的限界とその衝撃処理は干渉判定の無効化とは独立に保持する。

カメラ履歴も実経路から作り、露光0.09秒と、その直前の補間点を時刻で保持する。内部刻みを追加したために固定32点で露光区間を切り捨てない。既存の7時刻露光・Gaussianぼかし2 px・画像noise・画像960×720・ボード形状・表示設定は保持する。

既存IMU観測は \(R_{B\mathrm{IMU}}^\top(0,0,-1)^\top\) に接平面の観測誤差を乗せた**単位重力方向**である。慣性加速度を含む生の加速度計specific forceやジャイロではない。この観測仕様を今回勝手に変更しない。動力学の実角速度・実角加速度・真のKを `SensorInputs` やDBの推定payloadへ追加しない。

## 推定・IKとの違い

今回変更するのは仮想物理世界である。剛性の連続密度、身体の共同候補、全cross、目標mixture、完全Gaussian/Bingham規準、直接K_estの凍結packetと実行ledgerは変更しない。推定・IKの補助モデルは従来の安定平衡 \(\theta_{\mathrm{eq}}(u;K)\) のままである。

そのため、振動中には「実身体は慣性を持つが補助モデルは準静的」というモデル差が生じる。推定が動的な過渡応答を正確に予測するようになったとは主張しない。動力学へ変えただけで剛性同定の精度や到達が改善すると扱わない。coreの法則・候補PDF・推定/IK/表示の同一性を変更して、この差を見かけ上消すことも行わない。

## 起動と検証

既存の起動コマンドで、新しい物理側が既定になる。

```bash
cd ~/catkin_ws
catkin build probtf_observation_fusion_demo --cmake-args -DPYTHON_EXECUTABLE=/usr/bin/python3
source devel/setup.bash
roslaunch probtf_observation_fusion_demo imu_marker.launch
```

既定の強減衰2.0・干渉判定OFFの最終sourceで、規定指令による240フレームを測定した。画像描画・ROS配信を含まないCPU計測であり、推定処理やRVizの描画性能とは別である。

| 計算 | 平均 | 95パーセンタイル |
|---|---:|---:|
| C++積分の呼出し | 0.154 ms | 0.174 ms |
| 物理フレーム全体（積分・実姿勢・カメラ履歴） | 1.081 ms | 1.222 ms |

同じ6関節モデルの関節4を平衡から0.03 radだけずらし、指令を保持した5秒試験では、既定の強減衰で行き過ぎずに収束した。終端の全関節角誤差normは約5.54e-10 rad、エネルギー収支残差は約3.0e-11 Jだった。別に0.1を明示した低減衰試験では同じ関節変位が32回零を横切り、振動しながら収束した。これは特定の初期変位試験であり、全指令での単調応答や無条件安定性の保証ではない。

別の10秒ROS実行は `no_sensors` 条件で、物理109.96 Hz、Joint39.23 Hz、IMU29.88 Hz、画像12.002 fps、IK2.95 Hzだった。画像は観測入力へ有効化していないが、独立のraw取得は継続した。全812取得をDBへ保存・処理し、publisherの812回のraw送信呼出しとgraceful ACKを確認した。独立subscriberの受信はJoint391・IMU298・画像120の計809件で、各topicの初回1件は受信できていない。全rawのネットワーク受信一致を確認したとは扱わない。分布は32公開の実wire hashが保存済みの同じ制御snapshotに一致した。物理1101フレームすべてで、干渉結果は未検証のnullだった。この短い動作は到達せず、剛性推定速度・他のセンサ条件の実時間性能・長時間の到達成功の検証には使わない。
