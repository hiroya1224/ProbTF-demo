# 2026年10月18日の理論整理と実装の対応

同日の追加指示による[物理側の動力学化](DYNAMIC_PHYSICS.md)では、仮想身体をC++で時間積分する。以下の推定・IKの補助平衡モデルは保持する。両者を区別し、従来の準静的sourceの実測は新しい動力学の性能とは扱わない。

原文は [THEORETICAL_FRAMEWORK_20261018.md](THEORETICAL_FRAMEWORK_20261018.md)。同日のユーザーによる全面改修依頼に基づく。10月17日の実験結果・実装説明は、その時点のsourceの記録として残す。本書の変更後の性能を示す記録として転用しない。

## 合意済みの変更と、今回選んだ実装方法

原文で未決定の項目には、以下を実装者の暫定既定として置いた。原文の合意そのものではない。

| 項目 | 今回の設定 | 適用範囲 |
|---|---|---|
| Joint publish | 実際に送った位置指令と速度の通知 | 物理の真の関節角を観測にしない |
| BFSの確率単位 | 有効なセンサイベントごと | 身体0.25、剛性0.10。通知・欠測・重複には適用しない |
| 剛性Reset | 初期のlog剛性分布 | 全質量の比較尺度を明記してKeepと比較 |
| 剛性evidence | 局所Laplace近似 | 枝の相対尺度だけ。候補密度のGaussian化ではない |
| 遅着 | 未予約の過去イベントを保存して明示停止 | 原データを残し、チェックポイントからの再処理を要求 |
| 実行参照 | 既存のsource時計0.5秒位置参照を維持 | 新軌道アルゴリズムや連続性の保証を追加しない |

設定は `config/moving_estimation.yaml` と `config/stiffness_identification.yaml` に置く。旧 `execution_stiffness` 設定と最新一件選択は、新しい既定経路から外した。同期 `live` と `prepared_playback` は旧combined-packetの明示的な診断モードであり、新しいセンサ別BFSの検証には使わない。その診断経路では剛性BFSを明示的に無効にする。

## 実機候補の保持と指令作用

実行中の指令を $u$、IKが試す指令を $c$ とする。コードの既存APIには `source_command` / `query_command`、`command` という名前も残るが、試行指令を実行済み指令と混同しない。

`MovingInference` は全リンクと保持環境の共同モーメント代理を保持し、身体候補はその身体変数への周辺で表す。全リンク交差と身体・環境交差を保持する。正規化された形状 $p_t$ とlog全質量 $a_t$ を別に記録し、

$$
\Upsilon_{{\rm real},t}(dx)=\exp(a_t)\,p_t(dx)
$$

と解釈する。初期の全体尺度をlog 0とするのは規約であり、候補が常に質量1だという仮定ではない。有効イベントの比較可能な代理evidenceのlog値を加算し、無観測では質量をそのまま保持する。これはBingham由来座標と画像chart補正を用いた代理evidenceであり、厳密なraw画素Bayes evidenceとは主張しない。Keep/Resetには同じ直前全質量を与え、BFSの遷移kernelが全質量を保持する規約にする。

同じ身体候補へ、捕捉した数値代表 $K_{\rm est}$ による

$$
\Delta\theta(c;K_{\rm est})=
\theta_{\rm eq}(c;K_{\rm est})-
\theta_{\rm eq}(u;K_{\rm est})
$$

を右作用させる。`FrozenActionKPacket` は推定器の元の密度記録・`command_proposal`と、現在指令での安定平衡anchorを区別して凍結する。新しいKが届くだけでは実行中の作用を切り替えない。完成したIK計画・同じlaw・同じK packetを一体で採用する。未選定Kの計画には宣言済みの直接関節作用を明記し、後から届いたKを混入させない。

実行した各区間の `ActionStep` には実際の始終指令・時刻・使用K・branch・出自を保存する。観測時刻への伝播と遅れた結果のcatchupは、このledgerを使う。後から最新Kで過去区間を再計算しない。制御workerへのledger転送は増分だが、workerは全区間を保持して必要な範囲を使う。身体をFKの一点から再生成しない。

## 時刻付きの取得・逐次更新

既定の `async` は `event_motion.AsyncMotionSession` と `async_workers` で実装する。目標は物理120 Hz、Joint40 Hz、IMU30 Hz、画像12 Hz。取得時刻は、実際に値を取得した物理tickの時刻である。期限を逃した公称時刻へ架空の観測を作らず、逃したdeadline数を記録する。推定が同じHzで完了するという意味ではない。

物理coordinator、camera描画・保存、推定、IK、ROS公開・描画は別processで実行する。各数値processに専用モデルを持たせる。これはOS上の実時間の期限を保証するものではない。

ROS公開側にも専用の物理参照モデルを置く。軌跡は増分で送り、全履歴を公開側で保持する。新しい計画のsnapshotと保存済みwire、全rawイベントを同じ出自のまま送り、公開側で描画・JSON化・保存する。転送sequenceとACK、公開PID・待ち時間・raw公開数を記録し、推定のdrain完了と最終表示の採用完了を区別する。

`sensor_event_store.SensorEventStore` はSQLite WALとfull同期で、イベントID・取得stamp・同時刻内sequence・実送信指令・raw pixels/IMU値を保存する。状態は `awaiting_payload` / `pending` / `processing` / `completed` などに分かれる。画像を先に予約することで、その画素生成待ちの間に後続時刻を追い越さない。別センサの同時刻イベントも別々に処理する。

IMUイベントではIMUだけ、画像イベントでは画像だけを融合する。最後の画像をプレビューに残しても、IMU更新で再観測として融合しない。Joint通知と比較ケースで無効なセンサもDBに残し、融合しなかった理由を明記する。原画像・取得値・指令通知を最新一件で置き換えない。SG補間は使わない。

画像生成用の真のカメラ姿勢・板姿勢は物理側の `acquisition_requests.jsonl` に限る。公開観測DBに入るのは生成した画素と取得metadataだけである。推定側は許可した入力キー・画像hash・時刻・frame indexを検証し、真の姿勢・剛性等の入力を拒否する。物理側の復旧journalは推定入力ではない。

最古の未完了イベントが予約・失敗・未処理の状態なら、それより先へ進まない。過去へ遅着した未予約イベントは `late_requires_replay` で保存して停止する。直前イベントの同一再送は恒等、内容の違う同一IDはエラーとする。再起動の状態復元とDBのackは自動的に一つのトランザクションにはならないため、無条件のexactly-once crash recoveryとは呼ばない。

動作終了後も未処理観測は時刻順にdrainする。物理動作終了と推定完了は別の状態である。早期終了ではDBと取得journal、未完了イベント・worker終了状態を `shutdown.jsonl` に残す。推定途中の終了を「全観測処理済み」と表示しない。

## 剛性の連続BFS

`stiffness_bayes_factor.ContinuousStiffnessBFS` はlog剛性空間の連続関数を再帰的に保持する。身体や目標を含む一つのbody+K共同状態は作らない。全身体の観測後の代理密度と、実際のKeep/Reset観測前混合の代理密度の比から因子を作る。環境を先に周辺化し、リンク周辺の独立な積で代用しない。

Keep密度を $f_{j-1}$、その全質量を $M_{j-1}$、初期Reset密度を $f_0$、新しい因子を $L_{K,j}$ とする。正のBFSを使う経路では、比較可能な枝尺度の規約の下でKeep/Reset混合を構成し、全体尺度と各枝のlog質量を別記録する。枝の積分が有限で比較可能であることを局所的な前提とする。

初期Resetの質量を $M_0$ とし、両枝をKeepの質量へそろえる規約では、

$$
f_j(x)=L_{K,j}(x)\left[(1-\rho_0)f_{j-1}(x)
+\rho_0\frac{M_{j-1}}{M_0}f_0(x)\right].
$$

ここで $Z_{\rm keep}=M_{j-1}^{-1}\int L_{K,j}f_{j-1}\,dx$、$Z_{\rm reset}=M_0^{-1}\int L_{K,j}f_0\,dx$ とする。log全質量には $\log[(1-\rho_0)Z_{\rm keep}+\rho_0 Z_{\rm reset}]$ を加算する。実装ではこれらの積分に明示した局所近似を使うため、記録する質量もその近似に依存する。

$$
\rho_j=\frac{\rho_0 Z_{\rm reset}}
 {(1-\rho_0)Z_{\rm keep}+\rho_0Z_{\rm reset}},\qquad \rho_0=0.10.
$$

連続密度とscoreは全因子履歴とlog-sum-expによって評価する。微小な正の枝をunderflowで削除しない。K_estはこの密度上で選ぶ計算用の代表であり、候補そのものを一点へ置き換えない。rho=0では既存の未正規化因子積へ戻す。

Laplace近似はevidence計算に限る。代表選定の一回更新点を収束済みmodeとみなさず、積分用modeを別に探索する。scoreの収束、負の対数密度Hessianの正定値性、差分刻みhとh/2での安定性、機械平衡を検査する。不正なHessianのclipや成功の偽装をしない。正当なevidenceが得られない場合は、保持事前と未消費因子・理由を記録し、新しい事後が得られたと表示しない。

全履歴を保持する密度の問い合わせは、履歴が増えるほど計算量も増える。全データを捨てずに処理することと、無制限に実時間推定できることは別である。

## IKと実行参照

一般的な目標測度 `Upsilon_goal` の空間や更新則を今回新たに定義したとは扱わない。既存の比較用目標と相対姿勢の代理密度を使い、認識の観測尤度による更新とは区別する。

同じlaw・目標の全成分・捕捉した直接Kを固定して、完全なGaussian/Bingham負のlog密度Jの勾配を一回評価する。全covariance、Gaussianのlog determinant、Binghamの正規化定数、mixtureのlog-sum-expを保つ。

位置二乗誤差期待値sは許容条件から削除した。初期visual候補の受理、連成QP、Armijo探索、内点修復の全てでsを使わない。既存の共通box制約と完全Jによる選定を使う。位置のRMS値を近距離診断に残しても、位置非増大の保証とは呼ばない。

実行は既存のsource時計0.5秒位置参照とservo制約を維持する。新planの参照不連続や有限端点の過走を解決したとは主張しない。K_exec廃止だけで軌道の連続性は保証されない。三回仮想IKホライゾンや撤回済み端点停止方式は使わない。

## 同一lawの表示と保護対象

予測・snapshot・公開JSONへ同じ `candidate_measure` と `sensor_event` を渡す。予測では質量・元の観測出自を保持し、形状のstate ID・時刻・指令・版だけを輸送後のlawへ対応させる。表示アダプタはこれらと実際の点モーメント照会を照合し、異なるlawのmetadataを拒否する。表示するIK用K_estも採用packetと一致させる。

今回、coreの法則とRViz設定を変更しない。粒子・軸・画像のサイズや標本数も変更しない。描画用の既存サンプリングと物理センサ雑音を、推定やIKのモンテカルロ積分と混同しない。
