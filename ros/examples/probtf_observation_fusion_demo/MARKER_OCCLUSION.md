# 接近によってマーカーが遮蔽される試験

ユーザーの「IMU＋markerのほうでIMUだけを試す」に続く「近づいたらマーカーが隠れる障害物のほうが自然」という指定に対応する。最初にマーカーを観測して接近し、固定された板による遮蔽後はIMUと保持した環境候補を使う。マーカーを最初から無効化する試験や、新たな目標事前を有効にする変更は含めない。

```bash
cd /home/leus/catkin_ws
catkin build probtf_observation_fusion_demo --no-deps --jobs 2 --make-args -j2
source devel/setup.bash
roslaunch probtf_observation_fusion_demo imu_marker.launch marker_occlusion:=true
```

`marker_occlusion:=false` は無効、指定省略は [物理シーン設定](config/switch_press_scene.yaml) に従う。標準設定は無効であり、無効時は元のカメラクラスと同じ画像を使う。この起動オプションは既定の `execution_mode:=simple` に適用する。IMU取付、ロボット・ボード・スイッチの配置、カメラの較正と画像サイズは直前のIMU＋marker試行と同じである。

## 制御目標の10 mm押込みと初期事前表示（10月19日追加）

マーカー相対の制御目標は `[0,-0.24,0.035]` mとし、従来のz=0.045 mからパネル奥の−zへ10 mm移した。制御規準と目標TF・点群は同じ設定／同じ共同lawを参照する。物理ボタンの形状・位置、実到達判定位置 `[0,-0.24,0.045]` m、6 mmの許容距離、到達後の指令停止は変更しない。この押込みは課題側の取付関係の指定であり、物理真値から目標を補正するものではない。

起動直後は、既存のframe 0のjoint通知一件だけから構成した観測ゼロの初期共同事前を表示する。`simple_reference.yaml` の `startup.prior_display_hold_s=3.0` 秒保持した後、物理時間と保留した観測の原取得順更新を開始する。ROSでは同じsnapshotの公開ACKから保持時間を数え、headlessではsnapshotの生成完了から数える。初期lawのmodal姿勢は剛体FKに一致し、同じlawが最初の観測の事前になる。ProbTFのO(P)補正平均を剛体FK位置へ再中心化せず、全共分散・交差も保持する。これ以前の実走値は押込みと表示holdの追加前に対応する。

## 到達時の指令保持（10月19日追加）

ユーザーの追加指定により、最小参照版は物理側の既存到達判定（現在の干渉無効設定では棒先端とスイッチの距離6 mm以内）の成功通知を受けた最初の物理tickで、実送信済み関節位置を保持する。以後の新しい指令選定と後着planの採用は停止する。到達前区間は実際に動いた区間として記録し、次区間から `reached_hold` と零指令増分を記録する。通知時刻・指令・plan出自は `reach_stop.jsonl`、後着plan不採用は `simple_plan_dispositions.jsonl` に残す。

これは課題の終了通知であり、真の位置・K等を推定へ入力する変更ではない。物理の速度や姿勢を上書きせず、同じ位置指令のもとで慣性・ばね・減衰を進める。取得・推定・同じlawの表示も180秒まで継続する。一時到達後に慣性等で6 mm範囲を外れても指令選定を再開しない。ランプは従来どおり現在の物理条件を示し、停止履歴と区別する。下記の実走結果は本追加前のsourceであり、保持機能の実績とは扱わない。

[停止の回帰テスト](tests/test_simple_reach_hold.py) は、最初の到達での実指令保持、到達と同時／その後の後着plan不採用、既採用Kとledgerの保持、物理・取得の継続、初期到達、範囲外へ戻っても再開しない動作、同じlawの表示専用更新を検証する。既存の有限実行・遮蔽・ROS描画のテストと合わせて82件が通過した。実走の到達有無や停止後の整定距離は、この回帰検証とは別の結果である。

## 固定する形状

板はmarker座標のxy平面に平行な不透明長方形である。位置は `[0, -0.155, 0.28]` m、幅と高さは `[0.36, 0.14]` m。画像では灰色値96を使い、RVizでは同じ中心・寸法を厚さ0.004 mの箱として描く。固定具を含む接触力学を追加したものではなく、既存の干渉検査は無効のままである。

遠方では上側のマーカーが見え、カメラが接近すると板の投影がボードへ重なる。板の位置は実行中に動かさない。手先距離・経過時間・推定状態を使う遮蔽開始条件はない。

## カメラ画像と観測

各画素のカメラrayをmarker座標へ移し、板の平面との交点が長方形内でカメラの手前にあるかを計算する。ボードが描かれている画素では、板とボードのカメラ奥行きを比較し、手前の面を描く。ボードの外では背景を無限遠として扱う。カメラのnear planeの扱いは元の描画と同じである。

この合成を各露光時点のsharp画像で行ってから、既存の7時点の時間積分・Gaussianぼかし・画像ノイズを一度適用する。履歴不足の初回は、既存どおり1時点を使う。既存の画像取得時刻・送信指令・画素hashを保持し、通常の検出器が実画素から検出・欠測を決める。観測イベントやセンサ設定を強制的に無効化しない。検出結果を作り替えたり、黒画像や保持画像へ置き換えたりしない。

板の形状、各画像の遮蔽割合、同じ画素の検出結果は `physical_camera_occlusion.jsonl` に原event ID・取得時刻・送信指令・画素hashとともに保存する。これは物理画像生成の診断であり、推定入力へ渡さない。物理設定の起動時上書きと解決後hashも記録する。推定器が受け取るのは従来の画素、較正、IMU観測、実指令履歴である。

## 遮蔽後の推定と動作

最初に実際の有効なマーカーを融合したときだけ、従来どおり `goal_observed=True` になる。以後、画像が欠測でもこの履歴を消さず、共同身体・環境候補を保持する。環境候補を真のスイッチ座標へ置き換えたり、独立した固定目標lawを追加したりしない。IMUによる既存の共同更新と身体・環境crossを通じた変化はそのまま残す。

遮蔽画像にはマーカー尤度・K因子・身体BFSを加えず、有効なIMU観測は従来どおり更新する。身体BFSはρ=0.25、K側BFSとK evidenceは無効。保持した同じ共同候補へ凍結Kの指令増分を作用させ、伝播平均の差の二乗を使う有限指令選定を続ける。画像欠測だけで新しい探索phaseや零指令を追加しない。

## 遮蔽画素計算の高速化

最初のNumPy版は近距離の画素配列演算に時間がかかり、180秒試行で描画中央値119.7 ms、検出中央値30.6 ms、画像の待ち行列が最大122.2秒になった。この低速試行を実時間動作の根拠にはしない。記録は [before_native](validation/marker_occlusion_20261019/before_native/) に分けて残す。

修正は同じ画素ごとのray／平面判定だけを、デモ専用の `libprobtf_physical_camera.so` へ移した。near clippingと投影、ボード描画、時間積分・ブラー・ノイズは既存の処理を使う。元のdouble演算の順序と境界比較を保持し、FMAを無効にしてコンパイルする。ProbTF core、身体・K推定のC++ライブラリは変更しない。

実catkinビルドで、3つの保存済み物理要求・各8回の計24対において、最終のノイズ・ブラー済み画素と診断値が元のNumPy版に完全一致した。単体計測では近距離描画中央値62.1 ms、同じ負荷下のNumPy参照は153.3 msだった。単体値は検出やIPCを含まず、CPU負荷でも変わるため、実走時の待ち時間は別に確認する。[一致と計時の記録](validation/marker_occlusion_20261019/mask_equivalence_and_perf.json)

## 検証の区別

画像生成の検証では、奥行きの逆転、板がnear planeより後ろにある場合、無効時の画素一致、各露光での遮蔽と一回のブラー・ノイズ、実検出器の初期検出と接近後欠測を確認する。身体更新の検証では、欠測時の共同候補の保持と、その後の有効IMU・同じlawの指令選定を確認する。

実際の閉ループ試行では、マーカー欠測が起きた原時刻、以後に融合したセンサ、継続した指令、物理到達と終端誤差を別々に記録する。保存済み物理経路の画像再描画で遮蔽できることは、新しい閉ループでも同じ経路を通る保証ではない。画像の自然な欠測と、有限な推定・K更新の精度や到達性能も区別する。

## C++版の180秒閉ループ試行

新しい初期状態からIMU＋markerをRVizへ配信し、物理180秒と全14,661件の保存・原取得順処理・推定drainを完了した。初期には上段のID 17・18・19を実画像から検出して融合した。最初の欠測は34.001秒、一度だけ34.418〜34.751秒に再検出し、34.835秒以降180秒まで欠測が続いた。時刻は全て元の画像取得時計である。

最終の欠測区間に取得したマーカー観測の融合は0件、IMU融合は173件だった。そのうち動作中に完了したIMU融合が162件、物理終了後のdrainで完了したものが11件である。この区間の214 planは全て目標を保持し、203 planが非零の指令増分を送り、199 planは欠測開始後に取得した観測を使った。動作中に使用した最新の有効観測の取得元は174.774秒だった。後着した過去画像を新しいマーカー観測として数えていない。

| 最短の物理手先距離 | 2.721 mm（60.005秒） |
| 180秒終端距離 | 11.819 mm |

画像の待ち行列はNumPy版より短くなったが、推定の情報遅延は残っており、全処理が実時間であるとは主張しない。観測と実指令履歴を保持して遅着分を処理し、動作終了後のdrainで動作を延長していない。全rawを処理したことは、間引きされた全取得を尤度融合した意味ではない。全試行で実際に融合した観測はIMU225件・画像14件である。

現在の距離判定では一時到達したが、終端保持はできていない。全21,386物理姿勢に対する棒と板の事後幾何検査では最小表面距離12.094 mmだった。これは棒と板だけの読取専用検査であり、無効のままの全干渉検査や接触力学を保証するものではない。

96ソース、6共有ライブラリ、保護対象214ファイル（RViz43個）のhashが実行中に不変であることを確認した。原時刻・実指令・frame・画素hash、同じcanonical law、身体BFSのρ=0.25・K側BFS／evidence無効の検査は不一致0件。全1,502テストが通過した（267.79秒、既存のhppfcl非推奨警告1件）。RVizでの板の位置・回転・寸法・色とカメラ設定の一致も実際のROSシリアライズを通して検証した。
