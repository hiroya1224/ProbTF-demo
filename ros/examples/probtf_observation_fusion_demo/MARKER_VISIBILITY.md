# マーカーの画像検出と有効推定待ちの分離

2026年10月17日の「マーカーが見えているのに探索行動を始める」指摘に対応する。画像検出が続いているときは、その場で有効な推定・制御snapshotを待つ。raw検出だけで接近を再開する変更ではない。

本書は、`AGENTS.md`、`REQUIREMENTS.md`、`REQUIREMENTS_SEQUENTIAL_UPDATE.md` の旧「有効な融合結果が届かなければ、raw検出中でも探索へ進む」条件に優先する。身体・固定目標・剛性の逐次更新、通常IK規準、探索patternやhold時間の要件は保持する。

## 旧条件で起きていたこと

asyncの旧visibleは、raw画像での検出だけでなく、最新推定で有効なマーカー候補があること、最後のraw欠測より新しい融合・IK captureがあること、有効な固定目標記憶があることを全て要求していた。policyはこれらを一つのbooleanとして受け取り、後段が未完了の場合もマーカー欠測と扱っていた。

そのため、停止後の0.35秒holdが終わっても新しい融合目標が届かないと、rawでは見えているのに探索を始めた。探索移動中に融合結果が届いて再停止すると、さらにその停止後の新観測を要求し、同じ動作を繰り返し得た。

K代表追従修正版・探索条件分離前sourceの凍結一覧SHA-256は `2372c7a714cb1047def6daac0eaec297a6fe5f466d0ece0a16c87c3ba70ad1d2`。旧ログでは次の移行があった。

| case | 探索開始 | raw画像 | 停止source時刻 | 採用目標の観測時刻 |
|---|---:|---|---:|---:|
| imu_marker | 8.7568 s | 全9ID検出。8.2979 s以降連続検出 | 8.3979 s | 7.4802 s |
| marker | 15.8872 s | 全9ID検出。15.3372 s以降連続検出 | 15.5451 s | 13.8573 s |

このrunのraw取得は約14.8 fps、推定完了は約1 Hzだった。画像の取得時系列と探索区間を照合すると、raw検出中の探索はimu_markerで36.400秒、markerで33.440秒あった。ただし旧ログにはpreviewをcoordinatorが消費した壁時計時刻がない。この照合は取得時刻によるもので、各瞬間にcoordinatorがどのpreviewを利用できたかの完全再生とは主張しない。

## 新しい条件

| 状態 | 動作 |
|---|---|
| 接近中に画像検出を失った、または有効な制御用観測が未準備 | 共通制約を守って減速停止する |
| 探索中にraw画像で再検出 | 融合を待って動き続けず、減速停止を始める |
| 停止後のholdが未完了 | 同じ停止点でholdを完了する |
| hold完了、raw検出あり、有効な停止後融合目標・IK採用待ち | `settling` のまま停止点で待つ |
| hold完了、raw検出あり、停止後取得の有効目標と同じlawのIK採用済み | 接近へ復帰する |
| hold完了、raw検出が再び欠落 | 既存の有界探索へ進む |

raw検出中の推定待ちでは、停止指令、停止source stamp、hold開始時刻とanchorを保持する。待っている間に探索waypointや振幅を進めず、新しい融合結果が届いた時刻からholdをやり直さない。探索中の再検出では速度を不連続に零へせず、従来の速度・加速度・関節・停止距離制約で減速する。

rawの輪郭検出は姿勢候補が有効という意味ではない。後段が候補を構成できない場合も、検出と有効推定待ちを区別して記録する。rawだけ、停止前の観測、古いgoal、未採用の新しい推定結果で接近へ戻さない。接近復帰には停止後取得の有効な観測、固定目標更新、同じlawとKの制御snapshot採用が必要である。

## APIと取得元記録

`MarkerSearchPolicy.plan(..., marker_detected=None)` にoptional引数を加える。asyncは、最後に完了したraw画像検出のbooleanを明示的に渡す。同期callerが省略した場合は、そのcallerの現在の完成観測から導く。マーカーセンサを利用しないケースでは探索を起動しない。

recordは次を区別する。

| field | 意味 |
|---|---|
| `marker_detected` | raw画像の検出。未使用センサではNone |
| `marker_observed` | 接近復帰に利用する有効観測側の判定 |
| `marker_visible` | 互換用の有効観測側field。画像検出だけの値ではない |
| `marker_detection_source` | `raw_image_preview` または同期の `current_observation` |
| `marker_detection_capture_index`、`marker_detection_stamp` | asyncで判定に用いた実previewの取得元 |
| `waiting_for_fused_marker_goal` | raw検出中、停止点で有効な停止後目標を待っている状態 |
| `marker_observation_stamp`、`marker_observation_since_stop` | 有効目標の元観測時刻と停止後取得の判定 |
| `observation_hold_source_stamp`、`observation_hold_started` | 復帰条件の基準となる停止とholdの時刻 |

raw取得元を現在の物理時刻へ付け替えない。最後に完了したpreviewと、融合・IKで用いた観測が異なる場合も、それぞれの取得元を残す。raw booleanを新しい座標変換候補へ昇格したり、Bayes因子として追加融合したりしない。

## 保持する条件と検証

全身体・目標lawとcross、Kの密度・代表履歴・指令作用、固定根元目標、同じ分布のIK・表示・次事前への対応を変更しない。関節5先行の探索pattern、初期0.06 rad・増分0.03 rad・上限0.18 rad・速度0.048 rad/s、各waypointの0.35秒hold、共通動作制約を保持する。画像・粒子・既存軸・目標軸・TF・RViz設定も変えない。オレンジ残像は実際の探索区間だけに適用し、推定待ちの静止を探索として着色しない。

policy専用26試験で、raw検出による探索の減速、融合待ちの停止点・hold時計保持、古い目標では復帰しないこと、新しい停止後目標で余分なholdなく復帰すること、raw再欠落時の探索再開を確認した。既存の同K・同law・表示データ・次事前の検証も維持する。async側でもraw検出と有効なsnapshotの採用を独立に進めた統合試験を行う。

条件分離後の39ファイルsource一覧SHA-256は `7403ad5724ec9ca1d6135e26059781ff41fad0062b2738c463d131bb62ee5142`。関連464試験が通過した。両ケースを各60秒実行し、判定に使ったpreviewのindex・stamp・検出boolean、有効目標・IKの取得元、policy遷移、局所servoが送った実指令を照合した。marker1177区間・IMU併用1198区間で、検出中の探索移動は0区間、推定待ちholdの速度と変位も厳密に0だった。停止後の有効目標・IK採用による復帰は3回・2回である。

この試行の最初の物理到達はmarker50.404秒、IMU併用38.191秒。60秒時点の棒先端距離は5.050 mm・4.079 mmで、既存の6 mm条件を満たし、全軌道に衝突はなかった。これは今回の到達結果であり、絶対リンク姿勢の推定誤差やKの同定精度が解決したという意味ではない。

全422制御周期について、実7チャネルを受信し、同じ共同分布・K・目標から18,568点照会、422目標TF、完全J・勾配・line search、124回の画像内ボード融合とBF更新・全covariance・実指令ledgerを再計算した。推定・IK・表示の取得元とパラメータは一致した。source39ファイルは実行前後で一致し、RViz35ファイルも変更前とバイト単位で一致、coreの変更はない。source別の実配信・数理照合と限界は [visible_marker_hold_20261017.json](validation/visible_marker_hold_20261017.json) に記録する。
