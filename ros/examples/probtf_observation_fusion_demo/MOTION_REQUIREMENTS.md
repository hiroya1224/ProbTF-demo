# 動作を伴う4ケース比較の追加要件

2026年10月16日のユーザー指示と訂正を記録する。元の数式・推定仕様は `REQUIREMENTS.md` を適用する。

## 訂正の根拠

ユーザーは、同じスイッチ場面で観測条件だけを変えた4本の動画を要求した。その後、no sensorでも到達成功する旧動画を指摘し、次のように訂正した。

> no sensor でたわみを入れないとかじゃなくて，更新が無いから結果的にたわみがないように振る舞うって話です．勝手なことをするな

旧版は過去の成功実行から取り出した指令CSVを全ケースへ送っていた。推定結果が指令に使われず、観測なしも同じ成功動作になった。この固定軌道の比較は到達性能の比較として無効であり、再使用してはならない。旧動画を新しい閉ループ比較の証拠として扱わない。

## 共通の場面と指令選定

入口は `no_sensors`、`imu`、`marker`、`imu_marker`。全ケースで身体、棒、カメラ、マーカー、パネル、重力ばねモデル、初期指令、候補分布、観測生成条件、指令選定処理、時間刻み、実行時間、表示条件を共通にする。ケース差は推定へ渡す観測リストだけである。

実行中の指令列は、各ケースの実際の推定結果から生成する。指令列・物理軌道・画像がケース間で一致することは要求しない。これらは観測の違いから生じる結果として記録する。同じ観測入力と既知入力からは、同じ指令が得られなければならない。

各時刻の処理は次の順とする。

1. 現在指令を物理側へ送り、全ケース共通の重力ばね平衡から実姿勢・画像・IMUを生成する。
2. 同じ指令・時刻の直接指定候補族を照会し、選択された観測リストで共通の推定・持ち上げ・融合を実行する。
3. 推定に使った同じ共同候補と混合重みを表示する。
4. 同じ共同候補から、既知の指令依存性を通して次の短い指令を選ぶ。
5. 次の時刻へ進む。

no sensorだけ物理側のたわみを無効化してはならない。事前分布も変更しない。空の観測集合による恒等更新の結果を、そのまま同じ指令選定処理へ渡す。更新されない候補が実際のたわみを補正できず外れることと、物理モデルを剛体へ変更することは異なる。センサ名による成功・失敗の条件分岐、真値による指令補正は禁止する。

## 推定と制御の情報境界

シミュレータの実関節角、実リンク姿勢、実カメラ姿勢、マーカー実配置、関節剛性、実際の到達誤差は、物理描画・観測生成・到達検証だけに使う。指令選定へ渡さない。

推定への動的入力は `SensorInputs` の時刻・送信指令・画像・IMU方向だけとする。既知入力は、直接指定の局所候補族とその右作用、URDF取付形状・関節限界、カメラ校正値、印刷マーカー寸法、マーカーから目標への既知関係、指令の速度・加速度上限である。

マーカーの根元相対配置は未知の分布として保持する。未検出時はその観測の恒等更新とし、実配置・正解角点で補完しない。IMUはlink_3の重力方向のみで、yawや絶対方位を追加しない。

今回の固定時刻の推定仕様は維持する。各観測時刻で同じ直接指定族から事前を照会し、その時刻の観測だけで更新する。未指定の時系列予測・剛性推定・過去事後の蓄積は追加しない。

## 同時候補を用いた指令選定

一回の選定中は観測時刻の共同候補と目標の変量を固定する。試行指令には、与えられた各局所候補の `right_joint_action` を作用させる。右回転座標の変換を `G_j=diag(I,R_delta^T)` とし、共同共分散を `G P G^T` で輸送する。リンク間・マーカーとの交差ブロックを独立周辺で再構成してはならない。

身体と未知マーカーが共同状態を共有するため、比較は同じ共同候補の `marker^-1 * hand` への明示的な相対照会を使う。位置はcoreの一次Gaussian代理、方位はcoreのBingham由来一次回転共分散から再表現する。既知のマーカー→目標関係における相対候補の密度を規準とし、位置のlog determinant・方位のlog normalizer・全混合成分のlog-sum-expを含める。独立でない身体と目標の共分散を単純加算しない。

位置と方位の交差共分散を含む共同依存は相対照会まで保持する。規準段階だけ、位置Gaussianと方位Binghamの積へ近似する。その最終積で位置・方位間の交差ブロックを使わないことを明示し、厳密な共同相対姿勢密度や物理成功確率とは説明しない。中間リンク・手先の直接端点表示は同じ元共同状態を参照し、比較用の積で置き換えない。

ユーザーの追加指摘により、平均やモードの感度から作った4〜7点だけを比較する方法は撤去する。さらに「通常のIKのように勾配から更新方向を決め、計算の軽い方を選ぶ」と指示されたため、毎周期に完全な負の対数規準の勾配を求め、1回の短い制約付き更新を行う。正規化項を含む目的関数全体を各試行指令で再計算した有限差分を使う。位置・方位の感度と共分散から作る前処理行列は方向・尺度の調整だけに使い、平均だけの勾配を完全規準の勾配と説明しない。必要な短いline searchで刻みを調整し、速度・加速度・関節範囲を守る。評価数・勾配・刻み幅・制約による動作を記録し、各周期に最適解へ収束させたとは主張しない。センサ別の制御器や、身体の真の姿勢を用いた予測へ置き換えない。

## 時刻と可視化

物理描画、観測、推定、指令、分布版は各20 Hzフレームで対応させる。古い指令の分布を現在のロボットへ重ねない。準備計算後の20 Hz再生と、推定計算自体の実時間性能は区別して説明する。

追加の高速化指示により、全ケース共通の指令速度上限を0.20 rad/s、加速度上限を0.60 rad/s²とする。画像も同時刻20 fpsで表示し、サイズを変えない。計算の高速化で分布・近似次数・交差共分散を変えてはならない。代数的に同一の収縮順序変更は、旧計算との一致を確認する。

不透明モデルは重力でたわんだ物理身体、半透明モデルは現在指令の剛体FK。RGB点群は同じ推定共同状態への原点・軸端点照会であり、物理真値へ再中心化しない。IKに用いた共同状態・重みと、表示の照会元の対応を記録・テストする。固定時刻で残る推定誤差を座標表示の補正で隠さない。

既存RViz設定全体を保持する。パーティクルサイズ、画像のサイズ、レイアウト、視点、軸長、標本数を変更しない。終了時の自動保存を含めて事前保存とバイト比較する。

## 判定・検証・保存

物理側の成功条件は、実際の棒先端が目標から6 mm以内に入り、それまで禁止干渉がないこと。接触力やボタン変形のモデルではない。推定した成功や予定軌道の終端を実成功と表示しない。物理成功・失敗の真値を指令選定や停止判断へ戻さない。

検証では、推定結果が指令へ実際に反映されること、空観測時の恒等更新、物理真値を隠した情報境界、指令作用での全交差共分散の保持、推定と実公開表示データの同一性、全ケース共通の物理モデルを確認する。観測なしの実動作が事前候補へ向かい、たわみを補正できていないことを数値と動画で確認する。観測ありの成功をあらかじめ合格条件や演出用分岐にしてはならない。

同じ画角・速度で4本を再録し、推定・制御・物理判定と対応する記録を残す。現在のブランチへ通常の `git commit` / `git push` を行う。動画のignoreは対象動画だけ `git add -f` する。無関係な変更を含めない。
