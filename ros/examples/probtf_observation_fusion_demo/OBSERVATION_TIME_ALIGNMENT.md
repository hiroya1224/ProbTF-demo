# 観測時刻・実指令・身体候補測度の対応

2026年10月18日・追記: 以下は共同バッチ方式の監査記録である。その後のユーザー指示により、既定をC++数値処理を使う逐次更新の反復へ変更する。各観測の参照lawは直前に更新済みのcanonical身体から構成し、START固定・開始時Reset・集約hazardを外す。原時刻・指令・実ledgerの保存は継続する。現行仕様は [CPP_SEQUENTIAL_INFERENCE.md](CPP_SEQUENTIAL_INFERENCE.md) を参照する。本書の旧方式で測った跳ね・過信・処理時間を新方式の結果へ付け替えない。新しい非線形再線形化アルゴリズムの導入は引き続き保留する。

2026年10月18日のユーザーからの時系列対応に関する質問を受けた現行実装の監査。再線形化案の導入は停止したままであり、本書は新しい推定方式の承認・導入を意味しない。

原観測ID・取得時刻・実送信指令・実行区間との対応は保持され、各観測尤度とK密度比の計算に使われる。ただし、取得時のオンライン身体lawそのものをrawへ添付して保存する実装ではない。前処理済みのバッチ開始身体lawと実ledgerから、後で各取得時刻の参照lawを再構成する。

## 実データ例

IMU＋Marker試行では、IMU `imu:00000146` は動作開始後1.234778404秒、画像 `image:00000148` は1.251444101秒に取得した別イベントである。取得時の関節2指令はそれぞれ−1.8815223729531618 rad、−1.8832250409493423 radであり、原DB・ledger・因子へ別々に渡す。画像は取得要求後約0.078秒で画素がreadyになっているが、取得時刻をそのready時刻へ変更しない。DBには取得clockとready/claim/completion wall clockを別に持つ。非画像のready wall記録はproducer側で渡したwallと同じ値を使うため、全センサの実DB書込遅延を正確に測る値とは扱わない。

身体workerは、各eventのframe indexが実ledger endpointのstampとcommandへ一致することを検査し、そのprefixだけで身体参照lawを輸送する。IMU0.410830736秒と画像0.418235540秒の例では、基準0.376659393秒からそれぞれ3区間と5区間を使う。画像とIMUを一つの取得時計へ付け替えていない。

## 重要な制限


現行 source の read-only 確認。再線形化その他の新方式は停止中で、production は変更していない。

## 1. prefix事後は保持するが、次の観測モデルの評価点は更新しない

親仮説 h のバッチ開始Gaussianを π₀,h、その固定座標を ξ とする。原取得時刻 tᵢ・指令 qᵢ への実区間作用を F₀ᵢ、その局所座標の全crossへの作用を Gᵢ とする。各観測のaffine尤度は、開始候補を取得指令へ写した F₀ᵢ*π₀,h から一度だけ構成する。概念的には Lᵢ,h⁰(ξ)=Σₖ wᵢₖ N(yᵢₖ;Hᵢₖ⁰ξ+bᵢₖ⁰,Rᵢₖ⁰) である。

解析融合は πᵢ,h(dξ)∝Lᵢ,h⁰(ξ)πᵢ₋₁,h(dξ) として、全Gaussian積枝、正規化項、混合質量、全crossを各prefixで保持する。過去観測を捨てているわけではない。観測iの直前・直後の測度は F₀ᵢ*πᵢ₋₁,h と F₀ᵢ*πᵢ,h として取得時刻のchartへ写される。全親の混合質量もそのprefixまでのevidenceで更新する。Kには環境を周辺化した全身体のこの前後比を渡し、FK(K,qᵢ)で評価する。終端qで全過去観測を評価しているわけではない。

ただし次の Lᵢ₊₁,h⁰ を作る際に、πᵢ,h の更新済み平均・共分散でcoreの非線形queryを再評価してはいない。次の因子も同じ開始候補の実区間輸送から作る。したがって「固定affine観測モデルに対するprefix Bayes更新」は保持するが、「毎観測後の新しい候補分布から、次の非線形観測分布を構成し直す時間更新」とは同一でない。

実装対応: joint_batch_inference.py の全因子構成後に fuse_gaussian_likelihood_factors_with_prefixes を一度呼ぶ部分、time_resolved_body_ratios.py の previous_evidences / before_logs / after_logs。

## 2. BFSの変化確率の集計と変化時刻の保存は別

有効観測N件についてp=.25なら、無変化の質量a_N=(1−p)^Nと少なくとも一回の変化の質量1−a_Nは正しく集計される。現行は最初に π₀⁽ᴺ⁾=a_N π_keep+(1−a_N)π_reset を置き、Resetをバッチ開始へまとめ、その後に全観測の尤度を掛ける。

逐次的な変化過程なら、各iで [(1−p) Fᵢ*πᵢ₋₁+p Rᵢ(Fᵢ*πᵢ₋₁)] へ Lᵢ を掛ける。変化前に得た観測と変化後の観測では、それぞれが説明する身体が異なる。両式は一般には一致しない。現行は「いつ変化したか」「複数回変化したか」を保存していない。Reset側でも環境周辺は保持するが、身体と環境の交差を独立redrawの仕様に従い零にする。

さらにprefix測度もバッチ全体のNを使う π₀⁽ᴺ⁾ から始まるため、最初の観測直前のpriorに後続の有効イベント数が入る。後続zの尤度を先に融合するという意味ではないが、真の逐次hazard過程の当時の測度とは異なる。K用prefixはこの明示されたバッチ近似内の履歴であり、原取得時刻ラベルだけを根拠に、元の因果的時間確率過程を保存したとは説明できない。

実装対応: joint_batch_inference.py の effective_count / log_keep / rho / reset_location、bayes_factor.py の transition_priors。

## 3. 物理の時間発展と候補の予測作用は異なる

仮想物理側は実θ・角速度を状態として、慣性・Coriolis・重力・ばね・減衰を実Δtで積分する。一方、推定の実区間ledgerに保存する増分は、同じ捕捉K・branchの補助平衡 θ_eq(K,c) から Δθ_aux=θ_eq(K,c_end)−θ_eq(K,c_start) として求める。この補助平衡差の計算には区間所要時間Δtも実速度状態も入らない。候補はこの角度差の右作用と G P Gᵀ によって輸送する。

時刻は、全区間の順序・連続性、原qᵢ、Kの採用区間、原観測との対応の検証に使っている。指令c(t)自体が時刻依存なので時間を完全に無視しているわけでもない。しかし同じ指令区間列・同じK割当の所要時間だけを伸縮しても、この候補輸送の増分は変わらない。実物理の過渡応答は変わる。指令一定の待機中も物理θは動き得るが、この予測の増分は零になる。

よって原時刻の実画像・IMUを保存していても、その時刻の身体予測測度が動力学的な時間発展を再現しているとは言えない。静的・準静的な補助モデルによる近似である。K側も各qᵢで静的FKを評価するので、動的な遅れを独立の速度状態として推定しているわけではない。

実装対応: async_stiffness.py の PhysicalActionEngine.increment、async_state.py の ActionStep / RecordedCommandPath / _recorded_action。

以上は、取得ID・原tᵢ・原qᵢと実ledgerが保たれていることを否定するものではない。それらの対応は保持されている。ただしその保存と、非線形・因果的・動的な元の候補測度過程の保存は別である。


画像生成は露光0.09秒内の7姿勢から画素を構成する一方、推定側では露光末尾の単一stamp/qの姿勢観測として扱っている。露光全区間の測度に対する画像尤度を積分している実装ではない。また、先に予約した画像payloadの遅延には順序blockで対応するが、処理済みcursorより前の未予約観測が新たに到着した場合は `late_requires_replay` とし、一般の遅着観測の自動巻戻し・再融合は実装していない。


## 観測の矛盾と共分散収縮の実測

ユーザーの「予想と異なる観測が大量に入ると、不当に分布を狭めるのではないか」という指摘について、現在の各Gaussian積枝では、凍結したH/Rを条件として共分散は $P_N^{-1}=P_0^{-1}+\sum_i H_i^\top R_i^{-1}H_i$ で決まる。観測の残差の大きさはこの式へ入らず、平均とevidenceへ入る。H/R自身やmixture質量は観測に依存するため、全推定の共分散が観測値に全く依存しないという意味ではない。

二つの仮説を比較するevidenceが両方とも低くても、相対的に良いReset側の事後質量は1へ近付き得る。その後に、全バッチを同じ潜在身体候補と凍結affine尤度の積で説明する限り、観測間の矛盾を時間的なモデル変化として扱ったことにはならない。単一枝が支配すると仮説間のbetween共分散もほぼ消える。

実際の異常seq3では、支配Reset枝の6関節・18回転座標の分散traceがMarkerで0.0253690→0.0154955 rad²（元の61.08%）、IMU＋Markerで0.0253690→0.0138345 rad²（54.53%）へ縮んだ。比較は末尾Bingham再表現前のraw Gaussianとし、取得指令の右作用による直交chart輸送を含む同じ回転座標群で行った。各枝の最大局所回転平均は約1.2/1.4 radと大きい一方、事後の各回転座標標準偏差は約0.017～0.035 radだった。既に確認した原観測への非線形再投影の大幅悪化と併せ、今回の異常更新で過信の危険が実際に現れていると判断する。分散の縮小だけを誤りの根拠にしているのではない。

これは正しい固定モデルの下で独立な観測を融合すること一般の問題ではなく、時間的な変化をバッチ先頭のResetへ集約し、局所affineモデルを遠方まで外挿した今回の近似の問題である。全ての跳ねの原因をこの一項だけで断定しない。再線形化案は引き続き停止している。
