# 処理時間の測定と変更範囲

2026年10月17日の測定を記録する。基準はBayes Factor Surpriseを導入した親版 `84cbcf2` の実配信であり、振幅を広げる探索と剛性候補の省力化を入れる前の結果である。最新ソースの全体Hzは、この基準値から推測せず再測定する。

## 601周期の段階別測定

IMU＋マーカー601周期・30シミュレーション秒の `cycle_work` は、平均654.323 ms、合計393.248秒だった。このタイマーだけの逆数は約1.528 Hzで、実公開の1.384755 Hzとは区別する。実公開Hzから見た平均更新間隔は約722 msである。`cycle_work` には後続の `estimation.jsonl` のJSON化・書込み、ROS公開、scene公開が含まれず、この差の内訳は個別測定していない。

| 処理 | 601周期の平均 |
| --- | ---: |
| 観測からの二仮説更新・融合・輸送・内部縮約 | 215.021 ms |
| 次の短い指令の選定 | 149.662 ms |
| 制御用Kの数値代表・現指令平衡の評価 | 107.243 ms |
| 描画データの生成・照合・画像／分布の保存 | 107.226 ms |
| snapshot用core点照会 | 38.869 ms |
| 物理平衡・カメラ画像・IMUの生成 | 26.280 ms |
| 新しい剛性密度比因子の登録 | 10.018 ms |
| 合計 `cycle_work` | 654.323 ms |

各行は既存タイマーの段階に対応する。215 msの推定の中で検出器・持ち上げ・融合・座標輸送・モーメント投影がそれぞれ何msか、107 msの保存でエンコードと実ディスク待ちが何msかは、この601周期の記録だけでは分離できない。

この基準実行では、Kの現在指令での平衡を1周期平均約15回、完全な累積密度を約16回評価していた。累積因子は開始時1個から終端601個に増える。因子数×密度評価数を、そのまま実際の未キャッシュ平衡solve数とは呼ばない。各履歴因子の未キャッシュ評価回数は別に計測していない。

マーカー単独の同じ記録は、`cycle_work` 合計160.047秒、タイマー上の約3.755 Hzで、実公開は3.404660 Hzだった。接近・停止・探索終了後保持の割合もケースごとに違うため、IMU処理一つの追加費用として両ケースの差を引き算しない。

## 独立した1周期の関数プロファイル

同じ凍結ソース・設定のIMU＋マーカーで、ウォームアップ後の2周期目を別プロセスでcProfile測定した。累積K因子は2個、ROS公開は含まず、cProfile自身の費用を含む。計測された周期全体は1.130秒であり、上記の非cProfile平均654 msと直接比較しない。

| 計測対象 | 回数・時間 |
| --- | ---: |
| 完全な規準の評価 | 9回 |
| 目標mixture成分 | 4成分 |
| 成分ごとの相対密度照会 | 36回 |
| 同じ候補への指令作用 `command_state` | 38回 |
| 共分散支持の検査・分解 `covariance_support` | 2491回、累積266.997 ms |
| 対称固有値分解 `numpy.linalg.eigh` | 3397回 |
| Bingham由来回転座標の構成 | 900回 |
| Bingham正規化定数（`integration_steps=480`） | 36回、累積26.006 ms |
| 指令選定 `control_step` 全体 | 292.040 ms |

共分散支持の累積時間は周期全体の各呼出し元を含む。関数の累積時間は入れ子で重複するので、上の値を足して処理時間の内訳を作らない。Bingham正規化の26 msは、この指令選定約292 msの約9%である。この1周期の測定では、遅さ全体をBingham正規化だけで説明する根拠はない。同一の不変状態に対する支持確認や変換の再構成も多く実行されている。

推定、仮説混合、伝播、指令選定でモンテカルロは使っていない。完全な目的関数の勾配を有限差分で求めるための複数評価と、目標の全mixture成分を足す計算がある。上記の9回・4成分・36照会は、少数の状態サンプルを確率分布の代わりに比較する処理ではない。物理側のカメラ露光やセンサ観測生成と、候補分布の推定計算も区別する。

## 制御用Kの平衡評価を必要な候補から行う変更

基準実装は、決定論的な起点すべての密度と現在指令での安定平衡を求めてから、最良の安定な起点を選んでいた。変更後も同じ全起点の完全な累積密度を評価して順位を定め、現在指令の安定平衡は、その順位で選定に必要な候補から評価する。選んだ起点、score、line search、反復数、終了理由、選定Kと全proposal値を変えない処理である。密度の履歴因子・観測mixture・身体分布を削減したり、K分布を一点へ置換する変更ではない。

旧 `84cbcf2` と新実装を別module・別identifier・別URDFロボットで呼び、同じ実観測結果を与えた短い比較を行った。IMU単独・マーカー単独・併用を各5周期、計15周期比較し、全proposal fieldと最適化経路がバイト単位で一致した。関連47テストも通過した。

| ケース | 旧K proposal平均 | 新K proposal平均 |
| --- | ---: | ---: |
| IMU単独・5周期 | 164.103 ms | 110.797 ms |
| マーカー単独・5周期 | 143.958 ms | 89.089 ms |
| IMU＋マーカー・5周期 | 133.722 ms | 78.027 ms |

併用の通常周期では現在指令の平衡評価が15回から1回、初回は17回から4回になった。完全な密度評価回数は維持している。これは短いK proposal比較の結果であり、それだけから601周期の全体Hzの改善を推測しない。その後の同期実配信の測定は次節に記録する。

新しい探索は、停止中心から0.02 radで始め、中心への各往復後に0.01 radずつ広げ、最大0.12 radの範囲で再検出まで巡回する。旧8秒の探索打ち切りと、実験自体の30秒終端は区別する。終端は `FINISHED` と最後の動作を表示する。親版の固定振幅の601周期やsource hashを、この新しい方針の完了・速度・精度の証拠へ読み替えない。

## 振幅拡大・K評価変更後の同期実配信

新しい同期sourceで323テストが通過し、マーカー単独・IMU併用を各30シミュレーション秒・601周期動かした。実5チャネル計1202周期、82,938件のcore点照会、1031回の二仮説融合・正規化evidence・全共同モーメント、1200回の同じKによる選定分布と次事前を照合した。保存source20ファイル・RViz設定35ファイルを保持し、最終の `FINISHED`／`Last action` の実scene heartbeatも確認した。根拠は [同期progressive実装の記録](validation/progressive_search_20261017.json) を参照する。

| ケース | 基準84cbcf2の実公開Hz | 新同期sourceの実公開Hz | 新runの終端物理距離 |
| --- | ---: | ---: | ---: |
| マーカー単独 | 3.404660 | 1.814245 | 59.790905 mm、未達 |
| IMU＋マーカー | 1.384755 | 1.488372 | 131.720150 mm、未達 |

マーカー単独は、振幅0.02→0.03 radの拡大を2回行い、両方で再検出して接近へ戻った。実棒先端の探索停止位置からの最大変位は14.050 mm・9.018 mmだった。新しい有効観測は旧runの61周期から430周期へ増え、動作・計算内容が変わっているため、Hz差をK評価変更だけの影響とは説明しない。上限0.12 radでの反復はこの自然runでは未到達で、別のテストで検証した。

IMU併用は両runとも局所探索へ入らず、全601周期の指令、実平衡角、実棒先端が旧版とバイト単位で一致した。この実行では同じ軌道で約1.385 Hzから約1.488 Hzになった。ただし独立した負荷条件での反復測定や、非同期方式の物理20 Hz・カメラ15 fpsを確認した結果ではない。

両runとも手先の絶対姿勢の過信は残る。終端位置誤差はマーカー単独465.219 mm、併用68.458 mm、95%Gaussian代理領域内は両方0/601時刻だった。動作・計算量・推定精度を別に評価する。次に要求された壁時計での非同期動作は [ASYNC_EXECUTION.md](ASYNC_EXECUTION.md) の別実装・別検証対象とする。
