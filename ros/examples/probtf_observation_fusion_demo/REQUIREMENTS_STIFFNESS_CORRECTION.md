## 0. 明示的な誤指示の撤回

元指示書第3節の以下は**誤指示なので無効**とする。

> 今回の4例を完成させるために、新しい剛性逆モデル、剛性推定器、IK、接触処理を追加しない。

正しくは、**各リンクの座標変換候補をIMU・マーカー観測から更新した後、その同時分布に基づく剛性パラメータの分布推定・更新まで必須**である。一方、独立のIK機能や接触・力センサ機能は今回要求しない。剛性の推定とIK／接触を一括して禁止したのは誤りだった。

ユーザーが指示した4入口は `no_sensors.launch`、`imu.launch`、`marker.launch`、`imu_marker.launch` で変更しない。全入口で**同じ**伝播・センサ別推定・後段融合・剛性更新のコードを使用し、追加する観測だけを変える。無観測のときにも実装は共通であり、事前の剛性分布を維持する。

## 1. 推定の主従とデータフロー

主たる状態は、指令 `u_t` で実世界に生じている各リンク間の座標変換候補 `X_t=(T_1,...,T_n)` の同時分布 `P_X^-(dX|u_t)`、およびセンサごとの観測を融合した `P_X^+(dX|u_t,y_t)` である。

1. 同じ指令・同じ更新前分布から、各センサの推定済み分布を作る。
2. 共通事前を補正する同一演算で後段融合し、**リンク間の交差共分散を含む** `P_X^+` を保持する。
3. **必須追加**：`P_X^-` と `P_X^+` が支持する各リンク変換を、補助的な `deflecomp` 力学モデルの予測と照合し、剛性 `K`（必要なら `x=log K`）の分布 `pi_K^- -> pi_K^+` を更新する。
4. 主側の `P_X^+` を、剛性モデルから再生成した分布に置換しない。剛性モデルが説明できない姿勢・依存も保持する。剛性分布は後続の目標指令候補の**初期提案**に使用するための補助的な記憶であり、身体の推定を支配するものではない。

**剛性推定の有無をセンサの種類や組合せで分岐させない。** IMU・マーカーはそれぞれ独立に推定分布を作り、その融合結果を一つの剛性推定器が受け取る。

## 2. 具体的に評価する剛性の情報

既存 `ros/examples/deflecomp/` の力学実装をまず検査して再利用すること。現在の `EquilibriumSolver` は、送信指令 `u`、剛性 `K` に対して準静的平衡姿勢 `theta_eq(u,K)` を解き、その姿勢から各リンク間変換を順運動学で計算できる。以下、その**補助モデルだけ**が予測するリンク変換列を `Phi_u(K)` と書く。ここで `Phi_u(K)` は本来の身体候補全体の定義でも、その支持の制限でもない。

推定のためには、観測による**身体候補の重みの変化**を剛性候補ごとに評価する。センサ後段融合による身体の同時分布について、その同じ支持・同じ局所座標上の事前・事後密度を `p_X^-`, `p_X^+` として、基本計算を

\[
\ell_t(K)
=\log p_X^+\!\left(\Phi_{u_t}(K)\right)
 -\log p_X^-\!\left(\Phi_{u_t}(K)\right)
\]

\[
\boxed{\pi_K^+(K)\propto\pi_K^-(K)\exp\{\ell_t(K)\}}
\]

とする。これは `p_X^+(X) \propto p_X^-(X) L_t(X)` が成り立つとき、観測尤度 `L_t(X)` を `Phi_u(K)` で評価することに対応する。**同じセンサ観測を再度独立な測定として入力する式ではない。** マーカーの世界配置など共有する未知量がある場合は、身体の周辺分布を得る際にその未知量を周辺化し、既知真値を代入しない。

この計算は、剛性モデルが予測する変換列の観測との整合度を評価するものであり、現実の身体変換が `Phi_u(K)` に必ず属するとは仮定しない。`K` の事後は「既存力学モデルの中で観測応答を説明する有効剛性」の分布である。

連続分布の支持が異なる・混合の対応が失われている・補助モデルの出力に密度比を定義できない場合、勝手に小さな分散を加えたり、標本MC・最近傍候補・代表姿勢だけで置換しない。どの入力・支持・演算が不足しているかを報告し、必要最小限の**正当化できる**実装に限る。精度や同定可能性を作り出すために、未知荷重、モデル誤差共分散、新たな剛性事前、未知マーカー配置の固定値等を発明しない。

## 3. 非MCの実装経路と全共分散

座標変換の伝播・融合と剛性推定の主経路でモンテカルロを用いない。既存文書で指定済みの高集中一次の同時Gaussian代理を用い、`p_X^\pm` を**リンク間・回転並進間の交差ブロックを持つ全共分散**として評価する。剛性の候補を `x=log K` で表す場合、既存 `deflecomp` の `x_est, P_est` と更新器の設計を参照し、必要な微分・最適化・Laplace近似は決定論的に行う。

同一の凍結した局所座標で `p_X^\pm=N(mu_\pm,P_\pm)` なら、剛性候補が予測する座標 `z_K=chart(Phi_u(K))` において

\[
\ell_t(K)
=\log\mathcal N(z_K;\mu_+,P_+)
 -\log\mathcal N(z_K;\mu_-,P_-)
\]

を全共分散で評価できる。支持が退化していれば支持部分空間上の密度・行列演算とし、無断jitterで可逆化しない。単峰Gaussian代理の適用条件が満たされない場合は、指定済みの成分・重みを保持し、都合よく単峰へつぶさない。どこまで解析計算が可能かを検証する。

`deflecomp` から流用するのは既知の平衡計算、ばね則、既存の明示的剛性事前と正当化できる数値処理である。`deflecomp` のように **剛性を一次推定状態に置いて身体姿勢をすべて生成する設計には戻さない。** 既存のURDF／質量情報があることと、それを観測で既知と判明したことを混同しない。

## 4. 4例共通の必須出力・受入テスト

- 共通の `pi_K^-`、および4入口それぞれの `pi_K^+`、剛性各成分の代表値・分散／共分散・情報の不足を記録する。剛性値の真値・物性値としての保証を主張しない。
- 無観測では `p_X^+=p_X^-` だけでなく、**`pi_K^+=pi_K^-` を計算上の恒等性として検証する。**
- IMUのみ・マーカーのみ・IMU＋マーカーで、個別の事前・剛性更新器を作らず、単独推定済み分布を後段融合した**同じ** `P_X^+` から剛性更新する。センサの欠如を観測値0として代入しない。
- `P_X^-`・`P_X^+` と剛性更新結果の時刻、送信指令、source ID、版を照合する。真のシミュレータ剛性を使って推定結果を選別・修正しない。
- リンク間の交差共分散を0にした不正な計算と、正しい全共分散での剛性評価の違いを、交差項が非零の解析的例で検証する。
- 同じ入力のセンサ順序を入れ替えても、融合身体分布と剛性更新が一致することを検証する。
- RVizの4例は引き続き必須。身体分布の表示はcoreの伝播・融合結果と同一であること。剛性推定は最低限、同じ版に紐づく数値として公開・保存し、RViz上でも確認できるようにする。表示のために別の剛性推定を計算しない。
- 完了報告では、上記剛性計算のコード位置、更新前後の分布、実行結果・テストを明示する。**剛性推定がない状態を完了とは報告しない。**

## 5. 既存要求の維持

第4章のBingham回転によるベクトル作用の高集中一次代理、全共分散の二項、coreを用いた本体計算、センサ別推定**後**の同一演算による融合、4つのlaunch、RViz実行、SOLID・YAGNI・KISS、元の設定ファイルの保護はすべて維持する。力センサ・接触処理・フルIK制御は追加しない。
