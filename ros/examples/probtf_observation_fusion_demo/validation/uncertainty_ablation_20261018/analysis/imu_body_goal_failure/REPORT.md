# IMU＋Marker・身体／目標oracle試行の実関節範囲停止

この試行は180秒完走ではない。初回6 mm以内は38.6624秒、最小距離2.8918 mmは54.1903秒だったが、その後離反し、最後に実行済みの物理時計68.8294秒では距離243.011 mmとなった。次の指令候補が関節範囲を出たため停止した。一時到達を、180秒の到達維持・安定動作と記録してはいけない。

解析は保存済みログのstream読取りと、保存済み6自由度線形実行モデルの一tick再計算だけである。推定の再実行、候補伝播、追加の平衡solve、物理動力学の再実行は行っていない。production推定・制御・core・設定は変更していない。

固定SPDモデルが無拘束の連続時間で安定であることは、過渡応答が関節範囲に収まることや、packet切替・物理遅れを含む閉ループが安定であることを意味しない。速度・加速度clipは現行productionどおり無効であり、本診断では追加していない。

## Kの変化と、真値援助の範囲

最後のK変更は67.674156秒で、範囲外提案の約1.164秒前である。関節2の数値変化は約−0.596%だった。その後の最後5packetでは同じKと密度IDを使っていた。従って最後の切替の大きなforce反転を「同時のK数値の跳ね」だけで説明することはできない。一方、それ以前のK変更が指令感度・経路へ影響した可能性を、この比較で除外したわけではない。全K変化時計・値・出自はJSONに残した。

最終使用Kは `[105.0995, 117.2848, 107.9580, 105.0807, 104.9730, 105.1036]` Nm/radで、推定元時計は10.607293秒だった。実行時の新観測へ付け替えていない。今回のoracle_body_goalではKは通常推定のままである。

身体と目標の真値援助は最後のrequestでも有効だった。専用truth ledgerのrequest372はsource68.5679052秒・同じ実指令に一致する。凍結helperのroutingは、6局所リンク中心をこの実身体へ、身体SDを0.01倍へ、根元目標を真姿勢・0.1 mm／0.001 rad幅へ変える。通常画像と再帰身体推定・K事後は変更しない。

このsourceの指令と実身体角度との差はL2で1.040472 radだった。例えば関節2は指令−1.9110762 radに対して実身体−1.0908795 radだった。身体oracleが現在の実姿勢を与えることと、その先の高速な物理応答を準静的K作用が正確に予測することは別である。動力学の遅れ・指令作用の近似・規準の局所近似・packet切替の影響を区別する必要がある。

最終sourceの全候補pickleはartifactが間に合わず残っていない。g/H/ID・truth ledger・実指令・K・fail-safe入力は保存されているため上の実行器再計算は可能だが、最終候補から完全Jの位置／方位／共分散微分を再生成する検証はしていない。専用truth入力の記録とhelperの接続確認を、最終全候補PDFの独立な幾何検算と偽らない。

179個のproduction/config/RViz source hashが試行setupと一致した。元入力ファイルのSHA256と、凍結診断helperのSHA照合も`failure_audit.json`へ保存した。有限な結果を隠すための分散操作、任意品質停止、規準変更は行っていない。
