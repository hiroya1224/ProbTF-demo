# IMU＋Marker・狭幅真値マーカー観測試行の初期関節範囲停止

本試行は要求180秒に対し0.911455秒で終了した部分試行である。初期距離369.596 mm、終端671.505 mm、最小距離は初期値のままで到達していない。次tickの指令が実際のURDF範囲を出たため停止した。180秒の終端値や、任意の品質閾値での停止として扱わない。

保存済みログと6自由度線形実行器だけを確認した。推定・FK・平衡・物理動力学の再実行は行っていない。元のproductionソース・規準・gain・RViz設定は変更していない。

## 停止した提案位置

最後の実行済み時刻は0.911455秒、範囲外の次tick終端は0.921620秒だった。関節2の下限は−2.3562 rad、最後に送った位置は−2.355702971 rad、直前速度は−3.043905342 rad/s。次に計算された位置−2.386497985 radが範囲を出た。この範囲外位置は送信されていない。

保存済みpacket、最後の位置・速度・dtから同じ行列指数を計算すると、次の提案位置を全6軸で最大差0で再現できた。独自の監査判定による停止や、NaN/Infによる破綻ではない。速度・加速度clipは通常経路どおり無効であり、診断で追加していない。

有効な目標規準が完成したpacketはrequest20と21の2個だけである。それ以前はwaiting_for_goalだった。

2packetのsource位置・g・Hは同じで、新旧局所勾配は採用時にも完全一致していた。switch時の勾配cosは1、加速度入力の段差は0である。よって、この失敗にpacket切替の急な反転を持ち出す必要はない。

最初のsource勾配normは1.2488975e8で、視野勾配は零。eta=1e−6なので静止からの指令加速度normは124.890 rad/s²となる。既存の局所モデルにおける無拘束平衡位置は関節1で約−192.857 rad、関節2で−45.962 rad、関節4で−261.996 radで、実関節範囲から大きく外れていた。

実行器はその平衡位置を位置指令として直接送る方式ではないが、$g_{local}(u)=g_s+H_s(u-u_s)$の二階系なので、その方向の大きな入力が生成される。元の範囲内で局所モデルを使い始めても、数値的にSPDのHがあるだけでは、運動が物理範囲内へ収まる保証はない。この試行は、約68秒でpacket切替と残速度が増幅した別のoracle_body_goal試行とは異なる。

最後の実行速度は関節1で−11.2843 rad/s、関節2で−3.0439 rad/sだった。指令がすでに境界に近づいてから、次tickの実範囲判定が作動した。

## Kは何を使っていたか

実行された2packetは同じK `[105.3334, 113.3914, 113.0629, 105.3334, 105.3538, 105.3335]` Nm/rad、同じ密度ID `cda35b6865...`を使っていた。使ったKの最小／最大は105.3334／113.3914 Nm/radである。推定source時計は0秒。

これは厳密には未更新の初期事前代表ではない。source0秒のIMU観測`imu:00000000`によるjob1のK更新が、物理0.302685秒で利用可能になっていた。画像`image:00000000`による次K更新は物理0.840892秒で到着したが、範囲外停止までに、それを捕捉した新しい勾配は採用されていない。記録上の最新Kと、実行器が使ったpacket内のKを区別する。

最初のK作用が正確だったという検証ではないが、この短い失敗中に数値Kの跳ねが生じたため、と説明する根拠はない。

## マーカー真値の入力と検証範囲

取得0、0.084093、0.506697秒の3画像に、検出が有効な場合だけ真のカメラ相対中央観測を与えた。位置SD0.1 mm・回転SD0.001 radで、欠測の補完はしていない。各元画像ID・原指令・native9 markerの記録は元ログに残る。

各専用ledgerの真のカメラ姿勢と真のマーカー姿勢から $T_{CM}=T_{BC}^{-1}T_{BM}$ を再計算すると、代入した行列との差は全3件で0だった。したがって、保存されたoracle入力の座標合成を取り違えた結果ではない。

一方、実行された最終候補そのものの完全artifactは保存が間に合わず、最後の完成artifactのsourceは0.285819秒であった。g/H・ID・実指令・K・fail-safe入力・oracle観測ledgerは保存されているため上の実行器検算は可能だが、最終候補から完全Jの項別勾配を再計算してはいない。別のMarker初回に対する共分散項分解を、このIMU試行で測ったものへ付け替えない。

179個の元production/config/RVizソースと、6個の凍結診断helperは試行開始時のSHAと一致した。`failure_audit.json`は入力SHA、全2有効packet、実使用K、指令、範囲外提案、oracle観測のchain照合を保存する。native観測の大きいpayloadはこの派生要約では省略し、原ファイルとSHAへの参照を残している。推定器で観測枝を削ったという意味ではない。
