# ProbTF 統合デモ：たわむアームと棒でスイッチへ連続接近する

フランジにカメラと長い剛体棒を取り付けた6軸アームが、AprilTagの下にあるボタンの手前へ接近する。
仮想カメラの新しい画像から毎回マーカー候補を構成し、複数の身体候補が予測する動作後の棒先端で
目標位置密度を評価して、非線形IKで次のばね基準角指令を解く。
初回のIK後は、接近を続けながら別スレッドで再観測画像のIKを計算し、次の指令先を更新する。
実先端が非干渉で目標へ到達するとランプが緑になる。
Gazeboや接触力学は使用しない。

## 起動

ROS Noetic、既存の`deflecomp_core`、`symaware_grasp`、`prob_artag_detector`の依存関係を使用する。
PythonにはPinocchio、NumPy、SciPy、PyYAML、AprilTag辞書を含むOpenCVが必要。
テストには`python3-pytest`も必要。

```bash
cd ~/catkin_ws
catkin build probtf_switch_press_demo --cmake-args -DPYTHON_EXECUTABLE=/usr/bin/python3
source devel/setup.bash
roslaunch probtf_switch_press_demo switch_press_demo.launch
```

一つのRVizで不透明な実アーム・棒と半透明の剛体モデル、パネル・マーカー・ボタン・ランプ、目標範囲、
関節とARマーカーのProbTF表示、実先端の軌跡、カメラの検出画像を表示する。Viewsの`Switch close-up`で先端付近を拡大できる。
水色が実軌跡。青・黄・紫の予測棒は`IK prediction rods (diagnostic)`を有効にすると確認できる。
剛体モデルは同じURDFに現在のばね基準角指令を与えた姿勢で、Alphaは0.25。実モデルは重力と関節ばねの平衡姿勢でAlphaは1。
現在の棒先端には身体候補による広がりを付けない。到達後は指令と表示を保持し、終了はCtrl-C。
起動後は初期姿勢を5秒間表示してから動き始める。画面に`INITIAL IK`、`CONTINUOUS APPROACH + IK`、更新番号、IK反復数を表示する。
連続接近中は実アームの移動とIKの更新が同時に進む。

`ProbTF robot joints`は既存の`probtf_rviz/ProbabilisticTF`表示。
`symaware_grasp/configs/simple_six_dof_prob_tf.yaml`と既存の`config_from_mapping`を使い、
表示中の実関節姿勢に追従した関節Bingham分布を構成する。6関節、手先、棒先端の8フレームを通常の関節ツリーで発行し、
代表軸の合成結果を実ロボットの各フレームに一致させる。Axis Lengthは75 mm、各フレーム180標本。
赤・緑・青はそれぞれX・Y・Z軸端の標本。点群は連続した関節誤差モデルからサンプルする。
これは既存デモの設定済み関節誤差モデルによる可視化であり、IKが使う3つの剛性候補とは別のモデルである。
IKの候補と重みは変えず、予測棒は診断表示で確認する。表示の実姿勢を制御器へ返す経路はない。

`ProbTF observed AR marker`は既存の`probtf_rviz/ProbabilisticPose`表示。
検出器のnative分布を、観測時のカメラ姿勢でbase_linkへ正確に左合成して発行する。
回転と並進の結合、混合重み、残差共分散を保ち、補助カメラの座標軸を表示しない。
ARマーカーのAxis Lengthは90 mm、200標本。表示用stampは描画時刻で、元の観測時刻をprovenanceへ保存する。
元の`marker_belief`は観測時刻のまま別途発行する。これにより到達後も古い動的TFへの参照切れを起こさず、最後の観測を保持できる。
ロボットは完全な最新snapshot、マーカーは最新の1姿勢を描き、軸・点群を履歴として追加しない。
受信が止まった際のFrame Timeoutはロボット2秒、ARマーカー1秒。

到達後、同じノードを初期姿勢から再実行する。

```bash
rosservice call /switch_press/replay "{}"
```

最初の動作を自分で開始したい場合は`autostart:=false`を付けて起動し、RVizを確認してから同じサービスを呼ぶ。
実行中の重複要求は受け付けない。サービスは開始要求を返し、IKと接近はメインループで実行する。
再実行の記録には別の日時付きディレクトリを作る。

記録先は既定で`/tmp/probtf_switch_press_demo/<日時>/`。既存の記録は上書きしない。

```bash
roslaunch probtf_switch_press_demo switch_press_demo.launch \
  output_dir:=/tmp/switch_press_my_run

# 同じ実時間の連続制御・画像経路を、ROS masterと画面なしで実行する。
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  rosrun probtf_switch_press_demo switch_press_demo.py --headless \
  --output /tmp/switch_press_headless
```

`rviz:=false`はROS出力を維持してRVizだけ省く。設定を変える場合は`config:=/absolute/path/config.yaml`を指定する。
他の実験と同時に動かす場合は、別の`ROS_MASTER_URI`を使用する。既存の実験の既定設定は変更していない。

## 既定場面と情報境界

棒は長さ325 mm、半径8 mm、質量275 g。従来の棒を半分に切った寸法・質量で、生成URDFに重心と円柱の慣性を含める。
棒の取付部300 gとカメラ120 gも形状・慣性を持ち、既存アームと合わせて重力と干渉検査に含める。
`EquilibriumSolver`が重力と線形関節ばねの平衡を解く。指令角はばねの基準角で、実現した関節角ではない。
実剛性は試行中固定し、制御側の代表候補と異なる。制御側は3組の剛性と正規化した重みを保持し、同定や候補重みの更新は行わない。
棒の短縮に合わせ、マーカーが画角に入る初期姿勢に調整している。
ロボットのbase_linkをworld座標で`[0.22, 0, 0]` mへ移し、パネルへ220 mm寄せている。
パネルのworld配置を保ったまま、制御・重力計算・干渉検査ではbase_linkを共通基準にする。
現在の初期実誤差は約403 mm。

マーカーは180 mmのAprilTag 36h11、ID 21。960×720画素、焦点距離720画素、歪みゼロの光学座標系を使用する。
既存のマーカーテクスチャをOpenCVで平面射影する。露光時間240 msの間の実カメラ姿勢を履歴から補間し、
7時点の投影画像を平均してモーションブラーを生成する。静止時にはこのブラーは消える。
Gaussianぼかしの標準偏差2.0 pxと、輝度ノイズの標準偏差8/255も画像へ加える。
この画像を既存の`ArucoCornerDetector`と`PoseMixtureEstimator`へ渡す。
検出器のadaptive covarianceを有効にし、画像内のマーカーをノイズ・ぼかし・微小移動で再検出した角点のばらつきを
8次元の観測共分散へ反映する。再検出のノイズ標準偏差は描画側の輝度ノイズ設定に合わせる。
カメラ画像では背景とマーカー平面を描く。アーム・棒などによる遮蔽や照明変化は再現しない。
正解の投影角点、レンダラーの相対姿勢、実関節角、実剛性、実マーカー世界姿勢を制御器へ渡す経路はない。
真値は撮像、実軌道の監視、表示と記録にだけ使用する。

マーカーから目標へのオフセットは`[0, -0.24, 0.045]` m。
目標はボタン表面から15 mm手前にあり、到達許容距離は6 mm。
物理的なボタンのストロークや反力は計算せず、非干渉での接近を緑ランプで示す。

## 候補の伝播と選定

各画像から単画像の相対変換候補を作り直す。これは履歴全体を融合した事後分布ではない。
並進の事前分布は既存推定器の平均ゼロ・分散`1e6 m²`のproperなGaussianで、全IPPE枝に共通。
角点共分散には0.5画素の床と、画像から求めた適応共分散を使う。
画像由来の混合候補と固定の身体候補の積を使う独立性を仮定する。

マーカーから目標への合成には`compose_with_deterministic_right`を使い、混合重みと回転・並進の結合を保つ。
各成分から48個のBingham回転標本を取り、`conditional_translation_mean`で条件付き平均を求める。
観測由来の残差Gaussianをそのままlogpdfで評価する。
各身体候補の現在と指令後の平衡を同じ候補IDで対応させ、
`inverse(FK(q_i(c))) @ FK(q_i(c + u))`を既知の棒先端へ作用させる。
現在平衡解は周期内でキャッシュし、候補ごとに別のwarm startを使う。
ゼロ指令では相対変換を厳密に恒等変換とする。

最終規準は`K(u) = sum_i v_i * p_goal(h_i(u))`。
身体・混合成分・回転標本の重みを含めてlog-sum-expで合計する。
成分別NLLの加重平均や、並進点群へのKDEには置き換えない。
同じ周期の全指令候補で同じ回転標本を使う。
代表候補による微分IKを初期値にして、`-log K(u)`をL-BFGS-Bで最小化する。
各身体の平衡式を暗黙微分して関節指令に対する姿勢のヤコビアンを求め、
Gaussian混合密度の微分と合成してIKの勾配を計算する。1回の反復上限は6回で、観測時からの指令増分の各成分は±0.12 rad以内。
最適化した指令とその縮小指令、既存の小指令、ゼロ指令を期待密度で順位付けし、経路条件を満たす最上位を採用する。
数値最適化の収束と反復上限による打ち切りは`cycles.json`で区別する。Kは指令を選ぶための期待密度であり、到達確率ではない。

移動ループは20 Hzを目標とし、最大速度0.08 rad/s、最大加速度0.30 rad/s²で絶対指令先を追う。
IKは専用の1スレッドで計算する。受け取る画像、撮像時刻、撮像時の指令を一組として保持し、
遅れて返った増分は必ず撮像時の指令へ加えて絶対指令先にする。指令先の更新時にも速度をリセットしない。
撮像時の候補座標を最新の手先へ付け替える処理は行わず、動作前後で同じ身体候補を使う。
制御器、実身体、移動時の予測干渉検査はそれぞれ別のPinocchioデータを所有する。

観測を更新できない場合は前の指令先までの追従を継続する。観測の有効期間は5秒で、その後は減速する。
4回続けて観測または安全な指令を得られない場合、120回のIK更新や60秒で未達の場合は失敗理由を記録して停止する。
非同期実行の計算時間はOSの負荷に依存するため、同じseedでも実時間の軌道が完全一致するとは限らない。

## 非干渉と実到達

既存のURDF衝突形状と分離軸検査を使う。アームと棒の円柱は包含する直方体で保守的に近似し、
パネル・ボタン・ランプも設定に一致する直方体とする。自己干渉や床との接触は今回の検査対象に含めない。
制御側は画像候補のモードから求めた環境配置と全身体候補で経路を検査する。
指令先を移動途中で更新するため、各実行ステップの接続区間も全身体候補で再検査する。
この検査でも観測時のフランジを基準にし、現在・途中・指令後の各姿勢へ同じ身体候補を使う。
これは観測分布全体に対する確率的な安全保証ではない。実世界側では別に実軌道を検査する。

指令は最大0.008 radの区間に分割し、衝突形状の対応点の移動上限が2 mmを超える区間を再分割する。
各途中点で平衡を解き直し、4 mm以上の分離軸の隙間下限を要求する。
これは余裕を持たせた準静的な離散検査で、一般的な連続衝突判定ではない。
実軌道で隙間条件を破ったら即時失敗とし、その後も成功に変更しない。姿勢を投影して障害物を通り抜ける処理はない。

ランプは実先端と実目標との距離が6 mm以内で、そこまでの実軌道が非干渉の場合にだけ緑になる。
推定誤差、期待密度、候補の分散、剛性の一致は点灯条件にしない。
候補表示は観測時点の実フランジを表示側だけで使って世界座標へ置き、動作中に最新フランジへ追従させない。

## 記録と検証

- `settings.yaml`、`robot.urdf`：使用した設定と質量を含む身体モデル。
- `summary.json`：seed、ソースの版とSHA-256、結果、到達時刻、最小隙間、最終誤差。
- `cycles.json`：観測のnative成分、選んだ指令、身体IDと重み、前後の平衡、予測棒・先端、目標標本、共通基準の姿勢と時刻。
  `ik`には反復ごとの指令・予測先端・期待尤度、収束状態と停止理由を保存する。
  `image_degradation`に露光・ぼかし・画像上の移動量、`pixel_covariance`に角点の8次元観測共分散を保存する。
- `phases.json`：初期姿勢、初回IK、連続接近、到達の遷移と時刻。
- `servo.json`：移動更新ごとの時刻、指令、速度、絶対指令先、採用した観測の経過時間、予測隙間、IK計算中かどうか。
- `trajectory.csv`：実際に送った補間指令、実平衡角、実先端軌跡、目標誤差、隙間と干渉判定。
  先端座標はbase_link基準。`cycles.json`の観測時手先姿勢は`reference_hand_base`と`reference_hand_world`を併記する。
- `camera_XX.png`、`camera_final_raw.png`、`camera_final_detection.png`：周期ごとの検出結果と最後の画像。
- `camera_clean_XX.png`、`camera_input_XX.png`：同じ終端姿勢の鮮明な画像と、実際に検出器へ渡した露光・ぼけ・ノイズ付き画像。

周期ごとのカメラ画像はローカルの記録先に保存し、Gitでは除外する。下記で比較する代表画像2枚はGitにも含める。

```bash
cd ~/catkin_ws/src/ProbTF-demo
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  /usr/bin/python3 -m pytest -q tests/probtf_switch_press_demo
```

検証では、ゼロ指令、同じ身体候補での前後対応、解析Gaussian混合との期待密度の一致、
退化共分散の拒否、両端が安全でも途中で干渉する経路、ランプ条件、画素からの推定、棒の質量の重力への反映を確認する。
期待尤度と平衡後先端の勾配は中心差分と照合し、実画像からのIKが反復によって目的関数を改善することも検証する。
IKを意図的に待たせた状態でも移動が継続すること、古い増分が撮像時の指令へ適用されること、
移動途中での再計画でも観測時の座標で障害物を検出すること、指令先の更新前後で速度・加速度制限を守ることを検証する。
ProbTFの代表軸が全8フレームで実ロボットのFKと一致すること、点群が3個の点質量へ縮退していないこと、
ARマーカーの回転・並進結合と観測時刻が表示でも保持されること、
カメラが動いた場合に画像が露光によって変化し、検出器がその画像から共分散を構成することを検証する。
